GhostAction：数万仓库被植入恶意 Actions 工作流，专偷云/AI 密钥并翻遍 git 历史（头条）

GitHub Actions · 2026-10-07 扩散 · StepSecurity / Socket / Apiiro 多方披露 500+ 账号 · 数万仓库 · 外传 193.32.204[.]199 · 窃 AWS / Anthropic / OpenAI / OpenRouter 凭证

2026-10-07，GhostAction 用两个高知名度维护者账号完成两次集中投递：其一，游戏引擎 pyxel（GitHub 约 18,420 星）作者 Takashi Kitao，自 13:20 UTC 起向 27 个仓库推送恶意工作流；其二，8 小时后的 21:10–21:26 UTC，Uber athenadriver 原作者 Henry Wu（henrywoo） 的账号在16 分钟窗口内向 318 个仓库推送同款文件。安全厂商 Socket 更新称，自 10-07 以来已有 500 多个账号向数万个仓库提交该工作流，其中不少是经被攻陷贡献者触达的组织级仓库。

投递手法：恶意工作流统一命名为 "Security Audit"（security-audit.yml）或 "GitHub Actions Security"（github_actions_security.yml），提交信息写成 Add security audit workflow / Update security audit workflow——一个读起来完全正常的"安全审计"。触发条件宽松：workflow_dispatch 手动触发 + 任意分支、任意标签的 push。

本轮新增能力（关键差异）：早期变种只偷 Actions 密钥；本轮保留该能力，同时新增对工作树与整个 git 历史的正则扫描。它用 fetch-depth: 0 拉取全部分支与标签，再用 13 类凭证正则同时匹配工作区文件与 git log -p --all 的原始 patch 文本。这意味着一件很反直觉的事：即使凭证早已从默认分支删除，只要还挂在一个陈旧分支或标签上，一样会被翻出来。

被偷什么：仓库里配置的 GitHub Actions 命名密钥（含 CI/CD 密钥），以及工作树与全历史中的云、AI、SaaS 凭证。13 类正则中，AWS 占 4 类（AKIA/ASIA 密钥 ID、按变量名匹配的 Secret Access Key、会话令牌），AI 服务占 3 类（Anthropic sk-ant-、OpenAI sk-proj-、OpenRouter），源码托管占 3 类（GitHub 经典/细粒度 PAT、GitLab token），另有 Google、Slack、SendGrid。对 AWS 还额外捕获每个 Key ID 前后两行，用 AKIA_CTX_START/AKIA_CTX_END 界定符单独解析。全部数据经 明文 HTTP 外传至硬编码 IP 193.32.204[.]199——与 9 月那一波同一地址，两段采集结果塞进同一个 POST。

为何值得关注：

  • CI/CD 是最信任的自动化层：流水线天然持有全部生产密钥，而工作流文件是仓库里最容易被忽略、最容易被"看起来正常"的改动。攻陷维护者账号，等于一次性拿到其名下所有仓库的执行上下文
  • 修复认知最容易错位：只轮换 Actions secret 对 git 历史里的凭证暴露毫无作用；只扫描 HEAD 看不见被删除的历史提交。必须删工作流 + 轮换 + 审计 fork 与镜像
  • 目标是"发布凭证"：若被偷的是 PyPI / npm / crates.io 的发布令牌，一次账号失守就会升级成下游供应链投毒。截至报道时尚未观察到恶意包发布

处置：确认仓库是否在 2026-08-31 之后被加入 security-audit.yml 或 github_actions_security.yml（有则按失陷处理）；删除所有分支上的恶意工作流，并审计 fork 与镜像中的同一文件；轮换所有可能进过仓库历史的工作树/历史凭证（AWS、Anthropic、OpenAI、OpenRouter、GitHub/GitLab 等）。

Citrix NetScaler CVE-2026-107406（CVSS v4.0 = 9.5）：SAML 部署的内存溢出可致 RCE/DoS

NetScaler ADC / NetScaler Gateway · 公告 CTX697191（10-08）· CWE-119 CVE-2026-107406 CVSS v4.0 = 9.5 · 修复 14.1-73.46 / 13.1-64.29 · 无在野证据 · 21,000+ 暴露实例

Citrix 发布安全公告 CTX697191，修复 CVE-2026-107406——一处 CWE-119 内存溢出，可在特定配置条件下造成远程代码执行或拒绝服务，CVSS v4.0 基础分 9.5（Critical），攻击向量要求无权限、无用户交互（攻击复杂度为高）。

  • 只与 SAML 角色相关：漏洞仅在设备被配置为 SAML 身份提供方（IdP）或服务提供方（SP）时适用，且不同版本范围不同。较新版本仅 IdP 角色暴露，更早的受支持版本两种角色都暴露。自查配置是否存在 add authentication samlAction（SP）或 add authentication samlIdPProfile（IdP）
  • 受影响范围：仅 IdP 受影响的是 14.1-73.37 – 14.1-73.41、13.1-64.23 – 13.1-64.28 及对应 FIPS/NDcPP 构建；SP 或 IdP 均受影响的是 < 14.1-73.37、< 13.1-64.23 及对应构建。使用 NetScaler 的 Secure Private Access Hybrid 部署同样受影响
  • 修复与发现：升级到 14.1-73.46、13.1-64.29、14.1-73.46 FIPS、13.1.37.283 及后续。Citrix 致谢 JPMorgan Chase XOR 团队的 Michael Tucker、Chew Keong Tan、Alex Bernier 及 Maxim Suhanov 报告；厂商称尚不知晓有未被缓解的在野利用

为何值得关注：这是 NetScaler 连续第三周的紧急补丁（9-27 起 88771/88772 在野、10-04 88779 入 KEV、本周 107406），暴露面超 21,000 台。最危险的误判是"版本号不等于安全"：14.1-73.41 与 13.1-64.28 正是上一枚 SAML 漏洞 88779 的修复版本，上周刚补过的团队会以为已是"最新"，但在 IdP 角色下它们仍然受影响。判定必须同时看构建号与 SAML 角色。

3 公开 PoC / 无 CVE

AnyDesk Linux「AnyPwn」：预认证堆溢出直达 root，公开 PoC 却无 CVE、无公告

AnyDesk for Linux 8.0.2 · 直连 TCP 7070 · 修复 8.0.3（6 月，静默）· 最新 8.1.0 CWE-190 → CWE-122 · 无 CVE · 公开 PoC 2026-10-08 · 发现者 Rick de Jager（V12）

研究员 Rick de Jager（V12） 于 10-08 在 GitHub 公开了一个可用利用，命名为 AnyPwn：针对 AnyDesk for Linux 8.0.2 的预认证远程代码执行，攻击者可在目标用户从未点击"接受"连接的情况下，经直连 TCP 7070 拿到 root。

  • 根因（整数溢出 → 堆溢出）：会话协议的 mode-5 流包处理器在算缓冲区大小时，把远程声明的载荷长度加了 16 字节对象头，却用了无溢出检查的 32 位算术。攻击者声明长度 0xFFFFFFF0，加 0x10 后在 32 位里回绕到 0，分配器只留极小缓冲，而对象仍按原始超长逻辑长度拷贝——一个字节即已越界，进而覆写相邻堆对象，最终以 ROP 链走到 system()。对应 CWE-190 → CWE-122
  • 披露姿态问题：AnyDesk 在 2026-06-23 就确认了缺陷、8.0.3（6 月）已修复，但 changelog 只写"修复了一个可能导致崩溃的 bug"，未分配 CVE、未发布公告。研究者称，PoC 视频发布后 AnyDesk 下架了 8.0.2 的下载构建
  • 范围与不确定性：利用是概率性的（需堆布局把目标对象排在溢出缓冲相邻处，否则服务崩溃），PoC 偏移量针对 8.0.2 这一构建；厂商称仅影响 Linux 直连、Windows/macOS 不受影响，但研究者用 Frida 验证同一缺陷代码路径也能经中继服务器触达（未完成整条中继链）。这不是 CVE-2025-27918（不同机制）

为何值得关注：漏洞本身危害很高（预认证、网络可达、root），但真正该记住的是"静默补丁 + 无 CVE"造成的可见性黑洞：资产系统靠 CVE 源识别、扫描器按 CVE 匹配、补丁流水线按严重性排序——三者在这类"没有编号的严重漏洞"面前全部失明。跑 8.0.2 及更早版本的 Linux 端点（跳板机、运维工作站、无人值守服务器）在约 4 个月里暴露在一个已有公开 PoC 的预认证 root 漏洞之下。没有 CVE 不等于没有风险，只等于没有可见性。

5 密码学 / 隐私基础设施

GoBalance 密钥恢复缺陷：暗网站点 .onion 地址可被劫持，Dread、Omega 已被顶替

GoBalance（Tor Onionbalance 的 Go 重写，随 EndGame 分发）· Searchlight Cyber 10-08 披露 无 CVE · 无官方修复 · 单条公开 descriptor 即可还原长期主密钥

安全公司 Searchlight Cyber 于 10-08 披露：用于帮助暗网服务抗 DDoS 的负载均衡工具 GoBalance 存在密钥恢复缺陷，攻击者仅凭公开信息即可还原控制某站点 .onion 地址的私钥，进而劫持该地址、把访客引向自己搭的仿冒站点。

  • 根因（加密实现错误）：一个 Tor 私钥长 64 字节，但 GoBalance 签名时只把前 32 字节传给签名器，丢掉后一半——而那半正是让每次签名的一次性随机数（nonce）保持隐藏的部分。失去它后 nonce 变成人人可算的固定值，于是单条已发布的 descriptor（Tor 网络里谁都能拉取）就足以还原站点的长期主密钥。由于泄露的是长期主密钥而非短时会话密钥，被还原后可长期为该地址签发有效记录
  • 影响范围（窄但高价值）：GoBalance 是 Tor Onionbalance 的 Go 重写版，随广泛使用的 EndGame DDoS 韧性工具包分发。原版 Onionbalance 与 Tor 本身不受影响；且仅当主密钥以 Tor 原生密钥格式存储时才受影响（GoBalance 自带安装工具会写更安全的格式，故并非所有实例都暴露）
  • 真实利用：暗网最大论坛之一 Dread 的两个 .onion 地址在 10-05 至 10-07 间被接管并指向竞品 Conclave；即便 Dread 起初归因于自身失误，第二个（备用）地址也被接管后，运营者确认"第三方软件漏洞"所致并迁移、要求用户改密。另一家暗网市场 Omega 于 10-08 确认受影响并迁移
  • 修复状态：截至 10-09 无官方修复、无 CVE、Tor 项目与维护者均无公告；一名独立研究者发布了补丁与可用 PoC（仅用测试密钥演示）

为何值得关注：这是"签名随机数重用"这一类经典密码学塌方（2010 年 PS3 代码签名被破即属同类）在隐私工具上的重演——而泄露通道竟是协议为了可发现性而主动公开的 descriptor，无需与受害者交互、被动观察即可取走主密钥。更要命的是韧性工具反噬身份：为抗 DDoS 而部署的组件，反而成了剥掉服务加密身份的那把刀。硬结论是：补丁无法撤销已泄露的密钥——任何发布过脆弱 descriptor 的站点，必须生成新密钥、迁到新 .onion 地址，并通过签名公告让用户确认新地址。

英国时尚零售商 ASOS 于 10-06 遭入侵，攻击者（自称 Xuanyewen）借用 ASOS 自家 App 推送通道向大量用户推送"我们已完全攻陷 Snowflake 实例"的勒索式弹窗（含 Telegram 链接）。经 48 小时调查，ASOS 确认数百万用户的详细档案被窃——姓名、送货与邮箱地址、电话、客户编号、出生日期，以及顾客在网站上的近期搜索词（如"reclaimed vintage""glamorous wide fit""Asos petite"）；ASOS 称支付卡信息与密码未被访问。入侵路径：攻击者冒充"可信联系人"骗取一名 ASOS 员工的登录凭据，再用该凭据访问 ASOS 所用的某些第三方平台上的数据（数据存储商 Snowflake 自查称其平台未被攻破）。ASOS 全球约 1,650 万–1,700 万用户。

9. 「Adception」：Google 广告借 Bing 重定向投毒，假 Claude 安装器推 ClickFix

Push Security 于 10-09 披露一个被命名为 "Adception" 的恶意广告活动：攻击者把合法的 Bing 搜索结果重定向（bing.com/ck/a）当作 Google 搜索广告的落地 URL，于是广告显示的域名是可信的 bing.com而非攻击者域名，借此绕过审核与用户警觉。链路为：Google 广告 → bing.com/ck/a（JS 转发）→ 一处被攻陷的正规 WordPress 站点（南美某零售商）→ claude-desk-code[.]com（伪造 Claude 下载页）。该页双层隐身（校验 Bing referrer / 特定浏览器头；直连只看到 404）：模仿 macOS 下载流程，显示 Anthropic 真实命令 curl -fsSL https://claude.ai/install.sh | bash，但"复制"按钮塞进剪贴板的是另一条命令——它打印"正在从官网下载"的假提示，实际解码指向 lake-90[.]com 的 Base64 URL、用 curl 静默下载 .dat 文件并管道进 macOS 的 zsh 执行。最终载荷未知；已识别同一工具包（内部代号 AcSig）的多个域名。这条链不利用任何软件漏洞，全靠滥用可信域名 + 让受害者亲手把命令粘进终端。

10. 执法与实测：FBI 再逮一名 ShinyHunters 嫌疑人；Pwn2Own Ireland 收官 98 个零日

FBI 局长 Kash Patel 于 10-09 宣布，又逮捕一名 ShinyHunters 疑似成员；据《纽约时报》，嫌疑人为加拿大籍、在宾夕法尼亚州落网，疑与 FBI 求职门户 FBIjobs.gov 被入侵一案相关（入口为第三方厂商托管的平台）。此前荷兰警方已于 9 月逮捕该组织一名疑似头目，FBI 称该组织已入侵逾 140 个组织、取得至少 7,000 万美元勒索款项。另一方面，Pwn2Own Ireland 2026 收官：研究者共演示 98 个零日利用，其中包含对已完全打补丁的 Google Pixel 10 的远程攻陷，赛事累计发出约 126 万美元奖金。

11. TP-Link 遭美国四州起诉；ISP 定制 Aginet 设备曝五枚漏洞

TP-Link 再添法律压力——佛罗里达、爱荷华、蒙大拿、内布拉斯加四州依消费者保护法提起诉讼，join 此前已起诉的德克萨斯；TP-Link 称这些诉讼"建立在错误前提之上"。同期，SEC Consult 公布了 ISP 定制版 TP-Link Aginet 设备的五枚漏洞，最严重的是 CVE-2025-30237。家用与 ISP 侧路由器长期是 DDoS 僵尸网络与"代理节点"的温床——结合 10-06 的 ClingSTUN、10-09 的 Midnight Mimosa，本月"廉价/预装设备"这条线已连续多起。
