微软 Exchange CVE-2026-96940：一个"弱授权"缺陷，任何一名员工的凭据就能翻看全租户邮箱

2026-10-06，微软在十月早期更新中带外发布 Exchange Server 补丁，修复 CVE-2026-96940（CVSS 3.1 = 8.8，CWE-287 授权校验不当）。它坏在"授权"而非"认证"：认证回答"你是谁"，授权回答"你能打开谁的信箱"。已登录的攻击者可访问同组织内其他用户的邮箱，读取邮件正文与附件，但无法跨租户。微软官方可利用性评级为"Exploitation More Likely"，并由研究员 Jan Mitchell 内部发现、暂无在野利用证据。最容易被误判的一点是：曾经装过 9 月 8 日例行补丁的管理员并未被覆盖——必须重新部署 V2 版本。

1 头条事件

微软 Exchange Server CVE-2026-96940（CVSS 8.8）：弱授权让已认证攻击者读取同租户任意邮箱（头条）

Exchange Server SE RTM / 2019 CU14·CU15 / 2016 CU23 · CWE-287 · 带外 V2 补丁 CVE-2026-96940 CVSS 3.1 = 8.8 · 公告 10-02 · MSRC 十月早期更新 10-06

这不是远程未认证的零日，而是一处"授权"缺陷——认证回答"你是谁"，授权回答"你能打开谁的信箱"，CVE-2026-96940 坏在第二道。已登录的攻击者可以访问同一组织内其他用户的邮箱，读取邮件正文与附件；微软明确它不能跨租户访问，也无证据显示已被在野利用。

为什么必须认真对待：

  • 门槛极低：向量 AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:H，只需一个可登录的普通邮箱账号、网络可达、低复杂度、无需用户交互。任何一次对外包、共享邮箱或服务账号的凭据泄露，都足以满足前提
  • "补丁已装"是假安全感：微软罕见地把 9 月例行更新重发为 V2 版——装过 9 月 8 日原版（当时修复了 9 个 Exchange 漏洞）的管理员并未被覆盖，必须重新部署 V2 包。系统使用带外通道提前发布，Exchange 团队强调"装上就完事"的假设不成立
  • 邮件是最高价值仓库：高管往来、HR、法务、财务附件的价值密度远高于多数业务系统，一次读写就可能构成可报告的数据泄露；漏权校验意味着系统不会拦下一个好奇的内部人或拿到了凭据的攻击者
  • 安全边界之内的信任问题：缺陷源于 Exchange 信任边界内部"容忍了弱授权"——提醒组织：每个被过度授权的服务账号，都是未来的一个 CVE

处置：对号安装 V2 更新，公网可达或互联网边缘的服务器优先；复核 Exchange Admin / Mailbox 审计日志中的异常读取模式（尤其 FullAccess、SendAs 委派是否在正常变更窗口外被授予）；收窄 Exchange 集成账号（归档 / DLP / 备份）的邮箱范围；对全部可访问 Exchange 的身份强制 MFA 并关闭基本身份验证。Exchange Online 已由微软服务端修复，云上客户无需操作；2016 / 2019 已过主流支持，仅 ESU 第 2 周期在册组织可获取更新。另有反馈称 V2 包会引入日历类应用 HTTP 500 报错，升级前建议小范围验证。

为何值得关注：这是信任边界内部的授权崩坏——不是外围城墙被攻破，而是门禁自己没核准"这扇门该不该由他来开"。对一台承担全组织通信的邮件系统而言，一个被窃取的普通账号就等于一把能开遍所有信箱的钥匙。

Dell System Update CVE-2026-86360（CVSS 9.6）：服务器固件更新工具被曝未认证直达 root

Dell System Update（DSU）< 2.3.0.0 · 路径穿越 · DSA-2026-324（10-01） CVE-2026-86360 CVSS 3.1 = 9.6 · 同批另修 4 枚高危 · 修复 2.3.0.0+

DSU 是企业 IT 用来给 PowerEdge 服务器（Linux 与 Windows）批量推送 BIOS / 固件 / 软件的 CLI 工具，运行这些操作本身就需要高权限，因此一旦被利用，等于直接绕过服务器的主安全边界。Dell 的措辞很直接：CVE-2026-86360 是一处路径穿越缺陷，未认证、具远程访问的攻击者可借此以 root 权限执行任意代码，可能造成应用与底层操作系统的完全沦陷。

  • 同批四枚高危：CVE-2026-86361（8.2，关键资源权限分配错误，本地提权）、CVE-2026-86362（8.2，访问控制不当，本地提权）、CVE-2026-63697（7.6，证书校验不当，高权限远程代码执行）、CVE-2026-71168（7.3，路径穿越）
  • 修复与状态：升级 DSU 2.3.0.0 或更高；Dell 未标记已在野利用，但嘱咐"尽早升级"。同一批还督促尽快修补两枚满分级 Container Storage Modules（CSM） 漏洞 CVE-2026-63688 / 63692
  • 历史教训：路径穿越早被 CISA 与 FBI 列为"不可原谅"的缺陷类别（2024 年 5 月起呼吁出厂前清除）；而 Dell 产品多次被国家级组织消费——朝鲜 Lazarus 曾借 dbutil 驱动（CVE-2021-21551）投放 Windows rootkit，UNC6201 自 2024 年中起利用 RecoverPoint 硬编码凭据（CVE-2026-22769）在 ESXi 上建隐藏网卡

为何值得关注："管理平面"上的未认证 RCE 是最危险的一类——它出现在本就该被最高信任的运维工具里，一旦落地，横向移动的起点就是数据中心最核心的资产。对跑 DSU 的运维团队，把"固件更新工具"纳入与业务系统同级的漏洞优先级，是这次更新真正的启示。

3 开源 / 供应链

makeplane Plane 六连 CVE：默认密钥 + OAuth 盲信，自托管项目管理工具可被直接接管

Plane < 1.4.0 · 2026-10-05/06 GitHub Advisory 公开 · 修复 1.4.0 CVE-2026-105641 CVSS 9.8 · CVE-2026-105640 CVSS 9.1 · 共 6 枚（105636–105641）

Plane 是热门的开源 Jira 替代品，自托管部署量不小。同一时段共 6 枚 CVE 公开，全部在 1.4.0 修复，两类缺陷叠加的后果是"要么凭默认密钥伪造签名，要么凭一个未验证邮箱直接登进别人账号"。

  • CVE-2026-105641（CVSS 9.8，CWE-798 硬编码凭据）：deployments/aio/community/ 与 deployments/cli/community/ 清单内置固定且公开的 SECRET_KEY 与 LIVE_SERVER_SECRET_KEY 默认值；顶层 setup.sh 只对开发用 Compose 路径随机化密钥，aio / cli 社区部署仍共享生产密钥。知道 SECRET_KEY 即可伪造 Django 签名值、接管账号或会话；知道 LIVE_SERVER_SECRET_KEY 可绕过 live-service 鉴权
  • CVE-2026-105640（CVSS 9.1，CWE-287 认证不当）：Plane 信任 Gitea OAuth 与自建 GitLab OAuth（关闭邮箱确认时）返回的邮箱，却不验证提供方是否真的验证过该邮箱归属。攻击者把自己 OAuth 身份的未验证邮箱改成受害者地址，Plane 会直接匹配到受害者的本地账号 → 不知道密码即可登录受害者账号。GitHub、GitLab.com、Google 因返回已验证邮箱不受影响

为何值得关注：这是自托管开源协作工具的系统性通病——默认密钥没改、OAuth 身份把"提供方返回的邮箱"当成"已验证邮箱"。攻击面不在公网边界，而在每个团队自己拉起的容器里。自建 Plane 的团队需尽快升到 1.4.0，并轮换 SECRET_KEY、LIVE_SERVER_SECRET_KEY，同时核查 OAuth 身份提供方的邮箱验证策略。

4 数据泄露 / 国家级

丹麦国家人口登记库（CPR）被撬：约 880 万公民姓名、地址与社保号外泄

Det Centrale Personregister（CPR）· 10-05 披露 · 借合法第三方通道 约 880 万条 · 含已故者与移居海外者 · 数字事务部长称"极其严重"

丹麦中央人口登记系统 CPR 发生"极其严重"的安全事件。未经授权者获取了约 880 万名登记者的姓名、地址与 CPR 号码（CPR 号即丹麦的社会保障号），受影响人群不仅包括现居丹麦者，也包括已故者与移居海外者。

  • 入侵路径是核心：攻击者并未直接攻破登记系统，而是先入侵了一家依法拥有 CPR 查询权限的丹麦企业，借其合法通道批量拉取数据——典型的"第三方信任通道滥用"
  • 未受影响者：采取姓名与地址保护（navne- og adressebeskyttelse）的登记人不在泄露范围内
  • 规模：丹麦人口约 600 万，但 CPR 库保存约 1100 万人记录，本次波及面接近库内绝大多数条目
  • 处置：CPR 管理机构已切断该企业访问权限，与专家、当局共同梳理事件经过，并向丹麦数据保护局（Datatilsynet）报案，警方介入调查；数字事务部长 Christina Egelund 已向议会委员会通报，要求对 CPR 系统做全面安全审查。截至 10-05 尚未确认攻击者身份

为何值得关注：国家登记库是身份基础设施的底座——姓名 + 地址 + 社保号是几乎所有下游服务（税务、银行、医疗、政务）的身份锚点。它被用于精准钓鱼与身份冒用的杠杆，远高于数据本身的标价。而"合法第三方权限"这个入口，既不触发越权告警，也不在常规边界防御视野内——这与本期的 Exchange 弱授权、Dell 未认证 RCE 是同一根因的三种表现：系统信任了不该无条件信任的调用方。数据已出，真正能减损的是事前反钓鱼警示——当局已提醒民众：即便来电者能报出姓名、地址、CPR 号，也不要提供密码或其他机密信息。

5 威胁情报 / IoT

ClingSTUN：把 24 个已知漏洞和"合法 STUN 服务器"拼成的物联网后门

FortiGuard Labs · 10-05 披露 · 多架构 Linux 后门 · 无独立 C2 链式利用 ≥24 个已知 CVE · 兼顾扩散 7 枚 · 借公网 STUN 隐蔽通信

FortiGuard Labs 发现一个 Linux 后门 ClingSTUN，特征是不靠新零日、而是链式利用至少 24 个已知（且早已修补）漏洞打进物联网设备，覆盖路由器、网络设备、监控系统与工业系统，涉及 D-Link、Realtek、Ivanti、TP-Link 等厂商。集合中最早的是 2021 年 Sunhillo SureLine 的命令注入（CVE-2021-36380，被 FAA 等航空机构使用），最新的是今年的 MeiG Smart FORGE_SLT711 命令注入（CVE-2026-36356）。

  • 隐蔽通信：不注册传统 C2，而是借助公网 STUN 服务器（帮助 NAT 后设备发现自身公网 IP / 端口映射的合法协议）获知被感染设备的外部映射并周期性回传；研究者未发现独立 C2 注册服务器，恶意流量混在大量正常 VoIP / WebRTC 类 STUN 流量里，难以与合法用途区分
  • 持久化与扩散：干扰设备看门狗定时器、主动杀掉竞争恶意软件进程，支持 x86-64、ARM、i386、MIPS、PowerPC 等多架构；自带 7 枚额外漏洞的硬编码利用用于横向扩散（Realtek、MVPower、TBK、Linksys、LB-LINK、China Mobile、KGUARD；最早 CVE-2014-8361）
  • 后果：被攻陷设备成为代理节点，攻击者借道企业出口 IP 发起活动，可能招致 IP 封禁、声誉损失、带宽消耗，甚至成为进入内网其他目标的跳板

为何值得关注：这不是"又一个僵尸网络"，而是对资产治理失败的确认——24 个漏洞全部是已修补的旧洞，攻击者只是在打没人更新过的设备。STUN 滥用尤其阴险：它普遍被防火墙与 IDS/IPS 放行，把一个合法协议变成了"暴在明处"的隐蔽通道。检测思路不是"封 STUN"，而是看行为是否符合设备角色——意外连接大量 STUN 端点、多个 UDP socket、反复出现带组标识与映射端口列表的自定义报文。

6. AWS Loom 三连 CVE + SageMaker 命令注入：AI Agent 控制面"socket 即管理员"

7. Spectre v2 新变种 BTR（CVE-2026-64507/64508）：几分钟内泄出 Linux root 密码哈希

VUSec（阿姆斯特丹自由大学）与圣安娜高等研究院披露 Spectre v2 新变种 Branch Target Reuse（BTR）（论文被 CCS 2026 接收，09-29 公开）。JIT 引擎复用内存时 CPU 不作废旧的分支预测条目，攻击者借此让处理器在旧目标地址"投机执行"新代码。Linux 上研究者用非特权的 classic BPF（Docker、Chrome 用作 seccomp / 包过滤）编排预测，命中运行中的 su 进程，以约 8 字节/秒取出内核内存并恢复 root 密码哈希——Intel Raptor Cove / Lion Cove 上平均 3 分钟 / 5 分钟内成功。影响 Intel、AMD、Arm 测试到的所有 CPU；修复已并入内核（cBPF 复用 BPF 区时对所有核心发 IBPB + JIT spraying 加固），7 月已 mainline。

8. PixelLeak：AI 编程代理把 1.3 万张内部截图贴到公开 GitHub
