VMware 虚拟化核心三连击：vCenter 认证绕过 + 目录遍历 RCE + VMXNET3 虚拟机逃逸（VMSA-2026-0006）

CVSS 9.8 / 9.8 / 9.3 · CWE-287 / CWE-22 / CWE-787 暂无在野·修复 8.0 U3k / ESXi 9.1.0.0200

Broadcom 于 7 月 29 日发布 VMSA-2026-0006，一次性披露影响 vCenter、ESX、Workstation、Fusion 及 Cloud Foundation 的 5 枚漏洞，其中 3 枚评为严重（9.8 / 9.8 / 9.3）。两枚 9.8 均位于 vCenter 且无需认证、仅需网络可达管理平面，可串联实现「绕过认证 → 任意代码执行」；第三枚为 VMXNET3 虚拟网卡越界写，构成虚拟机逃逸至 ESXi 宿主机。目前 Broadcom 称尚无在野证据，但公告一出 PoC 研发窗口极短。

漏洞机制/攻击方式：

  • 类型：认证绕过（CWE-287）/ 目录遍历（CWE-22）/ 越界写（CWE-787）
  • 攻击方式：CVE-2026-59309 仅需网络可达 vCenter 管理端口即可绕过认证；CVE-2026-59310 借路径遍历在 vCenter 落地 payload；CVE-2026-47876 从已控 VM 内以本地管理员触发宿主机代码执行
  • 影响范围：vCenter 8.0（修 8.0 U3k）、Cloud/Sphere Foundation 9.1.x（9.1.0.0300）、9.0.x（9.0.2.0100）、Cloud Foundation 5.x；ESX 修 ESXi-9.1.0.0200 / 9.0.2.0100 / 80U3k 等
  • 后果：vCenter 是几乎所有 VMware 部署的控制平面，未认证 RCE 或 VM 逃逸等于整张数据中心失守

值得关注的原因：

  • vCenter 与 ESXi 处于企业虚拟化的「心脏」位置，未认证 RCE + 逃逸是最典型的「数据中心级」灾难原语
  • 两枚 9.8 同处 vCenter，可压缩攻击链：绕过认证后借目录遍历直接落地代码
  • 暂无在野 ≠ 安全，公告发布后 PoC 研发周期常以天计，互联网可达的 vCenter 须优先快修

明尼苏达州 30+ 水厂遭协同网攻 + CISA CI Fortify 隔离指南

关键基础设施 OT 事件 调查中·关基韧性受考

Arista VCO CVE-2026-16812（CVSS 10.0）在野零日 KEV 大限今日

CVE-2026-16812 · CWE-78 已确认在野·大限 7/30

Arista VeloCloud Orchestrator（VCO）on-prem 存在未认证 OS 命令注入（CVSS 10.0），已被确认在野。VCO 是 SD-WAN 控制平面，管理策略、路由、凭据与所有受管 Edge。Arista 7/27 发布 Advisory 0144，CISA 同日入 KEV，联邦整改大限即为今日 7/30。Arista 公开三个利用 IP（8.19.75.217 / 206.72.242.124 / 206.72.242.162），VCO 默认暴露且无配置项可关闭。

4 中高危

Fastjson 1.x CVE-2026-16723（CVSS 9.0）在野无补丁 RCE

暂无官方补丁 · CWE-502 在野·须 SafeMode

Alibaba Fastjson 1.x（1.2.68–1.2.83）存在无需认证、无需 AutoType、无需 gadget 的 RCE（CVSS 9.0）。研究者 7/21 负责任披露，ThreatBook 7/22 确认在野，Imperva 随后观测到针对金融、医疗、计算、零售行业的攻击流量。1.x 已终止维护，Alibaba 无补丁，仅能启用 SafeMode 或迁移 Fastjson2。KEV 仍标「none」与两家厂商确认在野直接矛盾。

5 中高危

AhnLab「Operation Double Barrel」朝鲜 APT 投毒 + Gunra 勒索

国家支持 APT · 供应链 持续活动

AhnLab ASEC 披露 Operation Double Barrel——自 2025 至 2026 上半年，国家支持组织滥用某国内金融安全软件漏洞，经水坑/鱼叉钓鱼诱导访问恶意 URL 后触发漏洞、植入后门；同一漏洞链亦投递 Gunra 勒索软件。两条攻击在初始渗透漏洞、SSH Key Fingerprint、下载与反向隧道基础设施上高度重合，暗示国家支持组织与 Gunra 在工具/基础设施层面存在共享或有限协作。
