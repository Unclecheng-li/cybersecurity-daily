GeoServer 五个洞串成一条链：没有一环是零日

CVE-2026-129244 等五个 · CVSS 3.1 9.8 PoC 已公开 · 国内 3,852 资产

两天里十家安全团队先后复现了同一条链。它不是某个组件的高危漏洞，是五个各自「中等偏上」的缺陷在默认配置下正好能连起来：一次未认证的 WFS 请求，最后一跳是 uid=0(root)。

CVE问题单独看
129244 WFS超长 storedQuery id 触发文件系统异常，回显数据目录绝对路径信息泄露
129243 OWSservice 带前缀时调度器截前缀、检查用原值，规则一条不命中授权绕过
120705 WFSGetFeatureById 的 id 未转义拼进 XML，可注入 xi:include文件读加 SSRF
129245 核心remember-me 签名密钥发行默认值就是 geoserver会话伪造
129242 JDBCResultSet.getObject 读 OTHER 列，反序列化不过滤代码执行

链条顺序就是上面这个顺序，一环给下一环递钥匙。报错回显给出 data_dir；服务名前缀绕过让匿名用户可以写存储查询；XInclude 把 users.xml 的口令摘要和 config.xml 的密钥一起读出来；默认密钥离线签出管理员 cookie，换到真实 JSESSIONID；最后用 REST 传一个恶意 HSQLDB、注册 JDBC 用户组服务，加载用户属性时反序列化执行。

默认发行包把两件本该分开的东西放在一起：JDBC 用户/角色模块和 HSQLDB 驱动都随标准包提供，而这个服务默认不注册。不注册就没人审它，但有管理员会话，一个 REST 请求就能把它注册上。

修复版本 3.0.2、2.28.6、2.27.7，官方十月十九日发布，十一月二十三日公布细节，二十四日出现完整脚本。受影响范围是 2.27.6 及以下、2.28.0 至 2.28.5、3.0.0 至 3.0.1。奇安信鹰图口径：国内风险资产 3,852 个，全球 18,412 个。

值得关注的原因：

  • 分级在这条链上失效了。五个里挑任何一个单独打分都到不了 9.8，但没有一个 9.8 能描述「串起来」。
  • 只修一个真的不够。官方公告写得很直白：修其中一处只能提高门槛，无法消除组合风险。
  • 默认值是最贵的负债。geoserver 这个字符串在发行版里躺了十几年，改它一次配置，不改就是链条最后一环免费。
  • 一个月没人动。补丁十月十九日就有，多数升级发生在脚本公开之后。
超长 id 换路径 前缀绕过写查询 XInclude 读密钥 默认密钥签 cookie REST 注册 JDBC 服务 反序列化拿 root

一天十条 KEV：六条在周六到期

CISA 2026.11.25 · 目录 1,805 条 Juniper 只给三天

十一月二十五日，CISA 一次往 KEV 里加了十条，其中六条的整改期限是十一月二十八日，也就是本周六。

产品问题期限
Juniper Session Smart构造 salt minion ID 触发命令注入，远程 root11-28
Vates Xen Orchestra空 JSON 对象构成的 token 绕过认证11-28
Mitel MiCollab AWV五个未认证缺陷，最高 10.011-28 / 12-09
Danfoss AK-SM 800A路径穿越与认证不当，可导出含内网信息的报告11-28 / 12-09

Juniper 这条最紧。CVE-2026-103406 的攻击面是一个 salt minion ID：只要能往 Salt 主控递一个自己造的标识，命令就在 root 上下文里跑。修复版本 7.0.5-14-lts、7.1.7-15-sts、7.2.3-8r2，没有 workaround。Juniper 在十一月二十四日更新里说已观察到至少一例恶意利用，所以 CISA 给的是三天而不是三周。

Xen Orchestra 是上周的闭环。十一月二十四日本报告的头条「一个空对象换来了管理员权限」讲的就是它，今天进了 KEV，攻击被追溯到十一月十日起。修复版本口径有分歧：厂商写 6.9.2 与 6.10.1，部分媒体转述成 6.9.1 与 6.10.0，升级前按厂商页面核对。厂商另一条建议容易被跳过：确认被入侵的环境要轮换所有密钥并重装，因为它管的是宿主机。

值得关注的原因：

  • 周六到期。六条期限落在周末，值班表上没人就是周一发现过期三天。
  • 全在控制面。路由管理、虚拟化管理、制冷控制器，都是配一次就再也不看的东西。
  • 2023 年的编号今天才进 KEV。老设备被重新捡起来打是常态，不是意外。
3 严重

PAN-OS：五月的本地提权，接在十月的远程执行后面

CVE-2026-46300 · PAN-SA-2026-0015 25 台设备被 root

Palo Alto 为 Linux 内核 XFRM ESP-in-TCP 的页缓存写缺陷补上 PAN-OS 侧修复。这个洞叫 Fragnesia，7.8，五月就公开了，单看没什么用，要先进系统。十月有人找到了「先进系统」那一步。

阶段用了什么结果
第一步PHP2Shell CVE-2026-109618，9.2nobody
第二步Fragnesia，覆写 pam.d/suroot
第三步替换 change_password.php命令中继

三段在同一个 HTTP 请求里跑完。第一段用 session.upload_progress 的 OOM 型 use-after-free 拿到 nobody；第二段往只读文件的页缓存里写，把 /etc/pam.d/su 换成 pam_permit.so，之后 su 不需要密码；第三段以 root 把 change_password.php 换成能执行命令的中继，原文件和 PAM 配置备份，health.php 留着保活。没有新端口，没有新守护进程。

Dream 的口径：用 FOFA 扫到 19,182 个 PAN-OS 管理门户，指纹识别约 5,000 台，筛出 240 个目标，最终 24 台防火墙加 1 台内部管理服务器被拿下。Unit 42 在十月二十九日验证过，并给出暴露比例：约 0.02% 的客户设备管理口对公网开放。

20 个 hotfix 覆盖 10.2、11.1、11.2、12.1、12.2 五条线。公告评级是 informational，不评 CVSS，理由是修的是上游内核问题。这个口径可以理解，但后果是扫描器不会为它报警，资产清单上不会出现红点。

值得关注的原因：

  • 两次补丁之间有一个月。PHP2Shell 十月三十日修全分支，Fragnesia 到十一月二十四日才修，中间正好是链子能跑的时间。
  • 本地提权评级永远偏低。7.8 会被排到后面，但它决定「进去之后能不能出来」。
  • 不留新端口。替换已有文件、复用已有端点，主机巡检看不出来，只能靠文件完整性。
  • 门只有一个。所有观察到的利用都从公网可达的管理口开始，这条防线比补丁便宜。
4 严重

Check Point：24 台管理服务器，cookie 是自己签的

CVE-2026-16232 加 CVE-2026-61500 22 家机构 · 17 个国家与地区

GreyNoise 的行动代号 GT13，身份未归属。22 家机构的 24 台 Security Management Server 被拿下，行业跨政府、金融、能源、交通、采矿、工程、制造。确认活动十月十七日到十一月二日，观察窗口从十月二日开始。

入口不是防火墙，是一台 Rejetto HTTP File Server。HFS 的 loginSrp1 会下发带 sid 的签名会话 cookie，而 sid 来自 JavaScript 的 Math.random()。攻击者连续登录收集输出，重建了 V8 伪随机数生成器的内部状态，还原出签名密钥，签出一个管理员会话。伪造的 cookie 里带 allow_session_ip_change:true，从任何 IP 都有效。

三天后往 /root/.ssh/authorized_keys 追加公钥，十月二十日把机器改成跳板：未认证 HTTP 服务上传工具，Nmap 加 Chisel 做反向代理。后渗透阶段跑的是 CVE-2026-16232，SmartConsole 认证绕过，七月修、七月二十五日 KEV 期限，四个月后还有设备没打。

一百多个管理任务里包括：复制防火墙数据库、导出内部 CA、签发新证书、卸载安全策略（实际相当于把防火墙关了），以及对 NetScaler、Ivanti、vCenter、Exchange、Oracle TNS、域控的探测。GreyNoise 统计到 99 个 IP、1,400 多次会话、800 多个命令行痕迹、1,200 多个文件操作。

十月二十六日那次批量证书任务在 24 台上全部失败，但错误日志回传时带着受害者 IP，还暴露出 /etc/ld.so.preload 指向 /usr/lib/libproc.so，一个疑似植入物的痕迹。GreyNoise 就是靠这批错误信息识别出受害者并通知的。

值得关注的原因：

  • 拿到管理服务器等于拿到整片网络。卸载策略这个动作不需要打任何一台防火墙。
  • PRNG 那条路要单独记。用 Math.random() 生成会话标识，样本够多就能反推状态。不是密码学问题，是用了不该用的随机源。
  • AI 的结论要谨慎读。GreyNoise 的依据是节奏、工具形态和行为自动化，没有捕获到模型调用记录。属于评估，不是证据。
5 严重

Expressway 落地：脚本是 AI 写的，日志里留了 nodeup

CVE-2026-76466 · 9.8 首例在野 · 期限已过三天

集群模式下的 Expressway-C 与 Expressway-E，硬编码凭据加证书校验不足，未认证远程拿 root。思科十月披露并修复，当时说没看到滥用。上周末变了，F6 在十一月二十六日说正在调查首例已观察到的利用。

攻击者先拿下两台面向互联网的 Expressway，通过其中一台进到内部网络里另外两个集群节点。拿到 root 后投放的 Python 脚本用途很具体：扫描 SMB 共享的文件与文件夹，与 SQL Server 和 WinRM 交互，在 GitLab 代码仓库里搜凭据。F6 说脚本形态表明操作者用了 AI 助手。

这句话和 Check Point 那条要放一起看。同一个星期，两家不同厂商的响应团队，都在报告里写了「疑似 AI 辅助」。这已经不算新闻点，快成标准字段了。

自查两条：Erlang 日志 erlang.log 里有没有 wombat@127.0.0.1 的节点加入记录；/mnt/harddisk/ 下有没有被投放的脚本。CISA 十一月二十日收录，整改期限十一月二十三日，已经过了三天。

值得关注的原因：

  • 硬编码凭据在集群模式里。「单机部署不受影响」这句话会让资产清单直接跳过它。
  • 两台变四台。集群节点之间的信任关系是设计出来的便利，也是现成的横向路径。
  • AI 辅助的落点是搜凭据。不是写 exploit，是写扫描和整理，这部分以前要人做几个小时。
6 事件

一天七份通报：77 万人的工资与逾期记录

土耳其 KVKK · 无 CVE 769,779 人

KVKK 十一月二十五日一次公布七份数据泄露通报，是这个月单批最多的一次。最大的一份来自消费信贷比价平台 InteraktifKredi，769,779 人。通报写得具体：攻击者事先拿到 ICRM 系统的私有访问地址和一名公司管理员的登录凭据，经海外服务器跳板的 VPN 连进销售面板。

字段清单长到需要单独列：姓名、身份证号、出生日期、婚姻状况、手机与邮箱、省市、就业状态、行业与职业、申报工资与发薪银行、配偶申报收入、房车持有标记、信用分、风险与额度、信贷账户、逾期记录、自动评分结果。

这不是「邮箱和密码泄露」的量级，是一个人能不能贷到款、能贷多少的完整底稿。

同一天另外六份：Yeditepe 大学十一月十五日起，入口是面向公网的 POS 应用背后组件，含健康与宗教信仰数据；Dorak 与 Ata Turizm 两家旅游集团十一月十九日同日遭勒索加密；Temeltaş 的会计员工点开钓鱼邮件，浏览器缓存的 VPN 凭据被拿走；World Triathlon 的 Metabase 泄露 1,673 人，含健康信息。

值得关注的原因：

  • 私有地址不等于访问控制。把管理面板放在猜不到的 URL 上只挡住了扫描器，挡不住从别处拿到链接的人。
  • 比价与信贷平台的数据密度极高。它天然聚合收入、负债、逾期，是身份欺诈的原材料。
  • 三份的起点是凭据。管理员凭据、VPN 凭据、浏览器缓存，没有一份的起点是零日。

速览区

7. JSPWiki：登录了，会话没换，10.0

CVE-2026-78114，CVSS 4.0 满分，CWE-384 会话固定。2.10.0 到 3.0.0 全平台受影响，修 3.0.1 与 2.12.6。认证成功后没有更换 session 标识，攻击者只要先塞一个已知标识，登录之后照样能用。同日还有 78111（附件页把 CSRF token 放进地址栏）与 78099（CSRF 可绕过），都在 3.0.1 修。ZoomEye 宽泛语法匹配到 626,685 条，是索引量不是装机量。验证办法很土：登录前后抓两次 cookie，看标识变没变。

8. Jenkins Script Security：9.9，一个部分限定名

CVE-2026-136835，9.9。1436 及更早版本处理 @Builder 注解时，builderStrategy 用部分限定类名就不会被拒绝，沙箱脚本可以逃逸。前提是攻击者有「定义并运行沙箱脚本」权限，但 Jenkins 里这个权限给得往往比想象中宽。

9. ICU4C：字符集名可以打进堆里

CVE-2026-137326，7.3，影响至 79.1。x11-compound-text 转换器克隆时共享 extraInfo 块却没有注册 safeClone 处理器，造成 use-after-free 与 double free。条件是应用把可控字符集名传给 ucnv_open()，同时调用 ucnv_setSubstString() 或做克隆。修在 PR 4297 与 4376。这类库的问题在于它在依赖链最底层，ldd 里能看到，资产清单里看不到。

10. Barracuda：改个时区就能 root

CVE-2026-111560，NVD 给 7.2，Mandiant 按 CVSS 4.0 给 8.6。六条产品线的时区字段没过滤 shell 元字符，管理员权限可注入命令并以 root 执行。已在 KEV 里。在 ESG 上还能和登录绕过 CVE-2026-116606 串起来，管理员权限这一步就不再是前提。

11. Ever Gauzy 与今天的高分堆

CVE-2026-135400，9.8。111.44.3 之前版本，jwt.strategy.ts 的每请求 JWT 校验直接接受了 getIfExists 的返回结果，用户不存在时校验等于空过。今天 NVD 窗口 9.0 以上还有三十条，多数是这个形状：不是加密写错，是「查不到就当通过」。

12. 今天该看的三件事

MONAI Label（CVE-2026-133968）的联邦整改期限就是今天。本周勒索受害者 337 个，比上周多两个，发得最多的是 N0N。本期六条 KEV 在十一月二十八日周六到期，值班表上要有人。
