今天 AI 一次演了三个角色：打手、人质、靶子

一个操作者把开放源码的 AI 代理平台对着 1,200 多个站点放了出去，指令不到 100 字，平均 23 小时打穿一个，总账约 5,000 美元。同一周，一个 13KB 的纯文本文件被浏览器静默存进下载目录，就把 Codex 的全局配置改了；一个推理服务把 HTTP 头原样写进请求标识，把整段 KV 缓存送到了攻击者手里。三件事里没有一行代码是"新写的错误"，全是功能按设计工作。第六件更值得记：一家大厂在 24 小时内撤回了自己的 AI 攻击结论。

1 严重

Cairn：23 小时打穿一个站，一次五十美元

NorForge 调查 · 9-25 起活动 · 10-19 报告 · Reuters 10-20 取证核实 1,200+ 站点被尝试 · 100+ 公司触达 · 总成本约 5,000 美元

这起事件最反常识的地方是它怎么被发现的：不是哪家防守方检测到了异常，而是攻击者把自己的控制面板裸奔在公网上，没设密码。NorForge 首席威胁研究员 Snorre Fagerland 在例行扫描互联网时，从 10 月 2 日前后开始陆续找到约 24 个暴露在外的 Cairn 实例（常见于 8000 端口、无登录），于是能近乎实时地看着代理干活。

Cairn 是一个开源的"通用问题求解引擎"：给代理一个目标和一个共享工作区，代理把发现贴到看板上，人类操作者随时补几句提示。它本来用于授权的渗透测试，这次被指向了别人的网店。

维度实际数字（NorForge 与 Reuters 口径）
活动起点2026-09-25，目标为美、加、澳、日的电商站点
扫描规模1,200 个以上站点被尝试，100 家以上公司的站点被触达
被点名的三家Deere、SharkNinja、Cummins（三家均称影响有限，Deere 称无证据显示敏感信息被读取）

指令长度不到 100 个汉字，之后代理自行跑了数小时

它们具体在干什么。三个集群里最忙的一个被 NorForge 标为 AIA0001，14 个面板挂着 1,100 个以上攻击项目，目标是拿到商店与支付系统的长期访问权。典型任务是"先在某个商店找到未认证代码执行，再放一个上传表单"——注意放的是存文件的表单，不是执行命令的表单，随时可以换成更狠的东西。研究者实地核验了两起：一家大型硬件零件供应商的 web shell 当时还活着；一家超大型美国零售商是被一个 cookie 设置打下来的——改一个 cookie，请求就被路由到有漏洞的后端。

顺手漏出来的东西比入侵本身更值得看。因为面板是开放的，受害者秘密也在里面：用 Trufflehog 扫出数百条凭据，其中 11% 仍然有效；另一个英文集群甚至把操作者自己的 SSH 登录信息也暴露了。攻击者的 opsec 失败，反过来成了受害者的告警源。

口径要注意。面板日志里出现过名为 claudecode_deepseek-v4.1-flash 的 worker 别名，暗示 Claude Code 的编排层驱动了某个模型，但 Reuters 未独立确认所用模型，只能当线索。另外，本刊 9-27 期速览曾按早期口径记过一组同类活动（用 Strix、Cairn、Hermes 等框架，27 家组织、119 个电商站点、逾 60 万张卡），那批的主体、工具与时间窗都不同，两组数字不能相加。

值得关注的原因：第一，这起事件里没有一枚新漏洞。被用的是未认证代码执行、SQL 注入、不安全反序列化、认证绕过、上传缺陷，全是老面孔；改变的是有人愿意让机器在一个站点上耐心磨 23 小时。人不这么干活，代理会。第二，50 美元一次把"批量尝试"从奢侈变成了默认选项，风险评估里那个"攻击者成本"的常数得重算。第三，检测思路要换：真正的信号不是 payload 长什么样，而是行为节奏——一个来源对同一批站点做长时间、多手法、低烈度的连续试探。顺带记一条给防守方的自查：先去数自己有多少个 admin 面板还挂在公网，这起案子里代理最终得手的路径之一，就是找到关联基础设施上的控制台。

下载目录里那个 AGENTS.md，改的是此后每一次会话

Forever Security · 10-22 报告 · 10-25 BleepingComputer 报道 无 CVE · 无补丁可打 · Codex 成功率 90% 以上

事情的起点很朴素：一家客户的 ~/Downloads 目录里有一个 13KB 的 AGENTS.md，长得像普通的工程规范。快到结尾的地方，它把"装一个包"写成了"先准备工具"，包名 function-color。客户那台机器上的编码代理正好就以这个目录为工作目录启动，于是照着做了——Forever Security 的监控在代码真正跑起来之前把这次安装拦下了，该包随后从 npm 下架。

研究者没能确定这个文件是怎么进来的，但证明了另一半：一个网页可以把一个名为 AGENTS.md 的文件静默存进下载目录。Chrome、Edge、Firefox 默认都存到那里、只弹个通知，Brave 在他们的测试里会先问一句。接着研究者用虚拟机复现了两条路径：

目标怎么被带的结果
OpenAI Codex文件指示代理把一条 [mcp_servers.*] 写进 ~/.codex/config.toml，或改掉 chatgpt_base_url无害载荷（开计算器）在 90% 以上的尝试里跑通；改的是全局配置，之后每一次会话都生效
Claude Code用一份 CLAUDE.md 让代理把项目设置指向一个"内部网关"API 请求带着用户的 OAuth token 发到研究者服务器；服务器代替模型作答并下发命令，约 50% 的测试里拿到代码执行
同一会话内通过子代理下发约 五分之一的测试里在本会话内执行成功

研究者写了一句很硬的结论："这里没有 OpenAI 或 Anthropic 可以打补丁的东西。"一个代理读它所在目录的 AGENTS.md 并照做，正是它被设计来做的事。风险不在模型，在你从哪个目录按下回车。据他们的遥测，数百家客户在下载目录里跑编码代理，仅 Claude Code 一个工具在该目录启动过 1,300 多次会话。

自查要落到具体文件上。~/.codex/config.toml 里有没有你没写过的 [mcp_servers.*]、chatgpt_base_url 是否被动过；项目的 .claude/settings.json 里有没有意外的 ANTHROPIC_BASE_URL 或代理设置；下载目录里有没有不是你自己下载的 AGENTS.md、CLAUDE.md。两条处置原则：删文件不够，代理改过的设置会留在配置里，得手动清；token 要换，因为泄露的 token 等于一个活着的登录。

值得关注的原因：第一，它把"工作目录"这个词从习惯变成了安全边界——一个从来没被写进任何安全基线的东西。第二，持久化落在全局配置而非项目里，一份 13KB 的纯文本改的是这台机器此后所有的代理会话，清理难度远高于普通钓鱼。第三，这类问题扫描器永远扫不到，没有 CVE、没有版本号、没有补丁号，只能靠流程：从项目根目录启动、读你不认识的指令文件、把审批提示和沙箱开着。这是"功能即攻击面"的教科书样本。

vLLM 一天八枚：一个 HTTP 头，把 KV 缓存送出去

10-25 批量公开 · GHSA-vfp2-c8pq-v6h6 · 当日高分段里 vllm 一家占 8 条 CVE-2026-116176 · 3.1 记 8.2 / 4.0 记 8.8 · CWE-918

先说最值得读的那一枚。OpenAIServing 把 HTTP 的 X-Request-Id 原样拷进 request_id，接着 P2pNcclConnector.parse_request_id 用一个很宽松的正则从中抽 host:port，没有白名单、没有协议检查、也不拦 IP 字面量。于是任何能发请求的调用方，只要在头里塞一个地址，就能让跑这个 connector 的 prefill worker 主动 ZMQ 外连到攻击者的主机，握手后交出 NCCL 通信的 unique_id，然后把那个请求的 KV 缓存用 ncclSend 送过去。

读到的不是"响应内容"，是提示词原文和前缀缓存的隐藏状态。换句话说，你以为在做推理，实际上在做导出。同一个原语还是 DoS：把地址指向一个黑洞，worker 就卡在那里，重复发几次就能压低服务能力。

项细节
编号与分数CVE-2026-116176，CVSS 3.1 8.2、4.0 8.8，CWE-918
影响版本vLLM 0.9.2 到 0.23.x，且启用了 --kv-transfer-config 的 P2pNcclConnector
修复方式0.24.0 直接把该 connector 删掉（PR #44854）
前置条件能访问 prefill worker：有有效 API key，或者压根没设 --api-key

同一天同一批还有 CVE-2026-116177：资源耗尽的拒绝服务，CVSS 4.0 8.7，修在 0.25.0。按当日新增记录统计，vllm-project 一家占了 8 条，是那天高分段里出现最多的厂商。

临时缓解有明确的做法：在网关或反向代理上丢弃或改写 X-Request-Id（只允许 UUID 或纯字母数字）；把 prefill 与 decode worker 放到隔离网段并加出站白名单，只允许连到批准的 decode 节点与 ZMQ 端口；给 API 端点强制认证，不要直接挂公网；把 NCCL unique_id 当秘密看，打完补丁重启 worker 让它轮换。检测上盯两件事：X-Request-Id 里出现 IP、主机名或冒号，以及 prefill worker 向未知目的地发起的 ZMQ 或 TCP 外连。

值得关注的原因：第一，KV 缓存是新的"内存里的明文"，它没有加密、没有审计、没有访问日志，绝大多数团队的资产清单里根本没有这个条目，但里面躺着用户的原始提示。第二，"删功能"正在成为 AI 栈的标准修复动作：这次不是打补丁，是把整个 connector 拿掉。做升级评估时得接受这个现实，功能可能直接消失。第三，这枚漏洞的形状很老派——把一个不可信输入当标识符拼接，和二十年前的日志注入是同一类错误，只是这次泄漏的东西换成了模型上下文。

Tailworm：一台设备被拿下，整个网格都能拿到 root

Erica Windisch / Cyberdione Labs · 10-25 发布 · 11 项发现 无 CVE · 无公告 · 无修复版本 · 实验室验证

Tailscale SSH 与传统 SSH 最大的区别是它不认密码也不认密钥，认设备。这个设计省掉了大量运维麻烦，也把整条信任链压在了一个前提上：网络里的设备都是可信的。Tailworm 报告动的就是这个前提。

根因说得很干净：Tailscale 的 SSH 由 tailscaled 提供，这个守护进程以 root 运行；而 SSH 的 Unix socket 端口转发是由这个 root 进程代做的，不是由登录用户做的。用报告里的说法，等于请大楼管理员替你开门，他的万能钥匙能开你自己那把开不了的门。四项高危发现：

发现做了什么实验室结果
1 · ssh -L被允许转发的一方可让 tailscaled 连到只有 root 能碰的 Unix socket，不需要 sudo，也不需要 docker 组拿到 root 与系统口令文件
2 · ssh -R可让 root 守护进程替换 root 拥有的 socket对特定服务以 root 执行命令
3 · 竞态检查与使用之间的时间差绕过路径白名单在未开 Tailnet Lock 的网格里抓到一枚有效的注册密钥，让一台流氓机器以受害者身份作为可信服务器入网；开了 Tailnet Lock 则失败
4 · conn25有权使用某一个 app 的用户，可以把共享 connector 指向任意目的地包括发放云凭据的元数据服务

其余七项覆盖：SSH 库里的内存耗尽循环、headscale 的内存耗尽、tailscale serve 的转发能打到本地 API 或其他 root socket，以及一个在 4,000 次测试里泄漏了 8 次特权响应的竞态。测试环境是 Tailscale 1.104.2 与 headscale 0.29.5，10 月 22 日至 24 日在实验室完成。

状态必须说清楚：截至 10 月 26 日，没有 CVE、没有安全公告、没有修复版本，PoC 也未公开。Tailscale 工程副总裁 Mike Shaver 在 Reddit 上回应说公司已收到报告、正与外部安全专家合作、已经发现并在修一些问题，同时不建议所有人关掉 Tailscale SSH；但并未逐条确认报告的技术结论。披露方式本身有争议：研究者称这是"报告了但未协调"，发布前几天才把报告与 PoC 发给 Tailscale 的安全联系人，社区里有人认为不够负责。

能做的只有配置。把 SSH 访问规则写成单源到单目的的对，删掉按身份或标签放行的宽规则——报告明确指出，这是实验室里唯一挡住扩散的那一道控制；能关端口转发就关（托管服务可按规则关，headscale 0.29.5 关不掉，只能把每一条 SSH 授权都当成给 root）；收窄 app connector 权限；删掉指向 Unix socket 的 serve 转发；开 node-key 过期；设备被攻陷就到控制面删除，重装系统不会撤销攻击者已经拷走的密钥。SSH check mode 只多加一道门，不修提权。

值得关注的原因：第一，身份即边界这句话的反面：ACL 本来是为了限制"谁能连谁"，一旦某台设备被拿下，ACL 就变成了攻击者的授权清单。第二，"可蠕虫"这个说法有争议，但争议本身值得记：报告自己写了，单源单目的规则就挡住了扩散，所以在宽规则环境里它像蠕虫，在窄规则环境里它只是一次提权。第三，没有 CVE 的漏洞最难走流程：资产库里没有版本号可查、扫描器没有插件、变更单没有对应的补丁号，全靠人读报告然后改配置。给它排期，只能按"配置变更"走，不能按"补丁"走。

Brotli 那个洞扩散开了：修在运行时里，不在你项目里

CVE-2026-111497 · 10-21 起修 · 本刊 10-23 期已报 Node.js 侧，本轮为下游扩散 CVSS 4.0 9.2 · 影响 Brotli 1.0.3 至 1.2.0 · 已进 8 个以上生态

先把上一层结论压成一句：问题在 Google 的 Brotli C 解码器里，不在 Express 里，所以只升 Express 没有用。这枚漏洞已经修到了 Node.js、Python 包、服务网格、代理与 .NET 里，本轮记的是扩散面与"还剩几个没修"。

还有 7 个捆绑副本没修（截至 10 月 26 日的追踪口径）：DuckDB、Apache Arrow 的捆绑构建、7-Zip-zstd、p7zip、EDK II 固件工具等；另有 5 个已在主分支修好但尚未发版。这就是这类漏洞最麻烦的地方：你的依赖树里是干净的，跑起来的二进制里是脏的。

三条输入路径，风险完全不同。第一，你的代码去取：Node 的 fetch() 会自动解 Brotli，Python 侧 requests、urllib3、aiohttp、装了 Brotli 扩展的 httpx 与 Scrapy 同理，对应 webhook、链接预览、爬虫、"从 URL 导入"这些功能，这条路上 WAF 完全看不见。第二，你收请求体：Express 5.0.0 至 5.3.0 与 body-parser 2.0.0 至 2.3.0 会解 Brotli 请求体（json()、raw()），这条路上 WAF 能拦。第三，你打开文件：.br 归档、Parquet 数据、woff2 字体、EDK II 固件工具、经 libjxl 的 JPEG XL，这条路跟 HTTP 无关。顺带一条冷知识：裸的 Node HTTP 服务不会自动解请求体，所以第二条路径是否成立，取决于你的框架怎么配。

时间线本身是个教训。上游那个改动提交在 2026-02-27，提交信息只写了"更早检测并报告无效流"，没有标明这是安全修复；含修复的版本 10 月 21 日才发，中间隔了 236 天；CVE 在 10 月 22 日公开，同日 GitHub 上出现 PoC。发现方是 OpenAI 用 Codex 做红队（Node.js 的致谢里写了 OpenAI Codex Security），Imperva 在官方 Node.js 镜像上多次尝试后拿到了代码执行。Juliano Rizzo 的评价是"比 PHP2Shell 更大"。

值得关注的原因：第一，补丁位置不在你以为的地方：容器镜像、发行版打包、内置副本三者版本可能各不相同，升完要确认跑起来的是哪一个，并且重启进程，老进程会继续用老的解码器。第二，236 天这个数字比 9.2 分更值得记：一个没被标成安全修复的提交，和一次真正发版之间，可以隔大半年。第三，架构决定风险：同样是这个库，做客户端去解别人给的数据就没人拦，做服务端收请求体还能靠 WAF 顶一下，去处理用户上传的归档文件则完全没人管。先数清楚自己有几条路径，再决定先修哪条。

6 高

Qualys 与 Ox Security 扫描 · Unit 42 于 10-25 14 点 15 分（PT）撤回更新 CVE-2026-109618 与 109619 · 服务器未修比例 99% 以上

今天这条的重点不在漏洞，在两个数字放在一起时的错位。一边是扫描结果：Qualys 与 Ox Security 的统计显示，可被 PHP2Shell 打下的服务器里，99% 以上至今仍未修补；互联网上73% 的 PHP 资产存在风险（扫描估算口径，不是确证受害数）。另一边是情报：Unit 42 在 10 月 25 日下午 2 点 15 分（太平洋时间）撤回了它 10 月 23 日的更新。

撤回的内容相当具体。原先的说法是：攻击者在滥用 PHP2Shell 之后用代理式 AI 平台做后渗透，其中一起针对欧洲某政府实体，在两小时内拿到口令哈希与多因素认证密钥，建立 NTLM 中继隧道进入 Active Directory，并尝试提权到域管。现在的表述改成：团队"最初以为"该攻击与 PHP2Shell 相关，目标确实是一个有漏洞的 PHP 应用，但"无法确认初始访问与这两个具体的 PHP2Shell CVE 相关"。The Hacker News 那篇报道与撤回是同一天，所以文中关于代理式 AI 与政府单位被入侵的细节，应当按未确认处理。

同一份报告里仍然站得住的部分：CYFIRMA 的第三版公告（10 月 24 日）描述了一场疑似与朝鲜有关联的活动——21 个被控节点对一份筛过的 216 台目标清单做慢速、低频探测，目标分布在政府、金融、物流、机场与航空、制造与在线交易行业，地域覆盖美、日、韩、泰、印尼、澳、印、新、阿联酋、沙特与欧盟。研究者强调节点一遇阻断或限速就轮换弃用，所以基于阈值的告警基本抓不到。归因以"中等可信度"给出，属于机构评估，不是已确认结论。

速览

7. SleeperWidget：250 个以上扩展，只有你看了广告才动手

微软浏览器漏洞研究团队发现一个恶意扩展集群，横跨 Edge 加载项、Chrome 网上应用店、Firefox 附加组件三个官方商店，至少 250 个。它们的共同点是平时无害：只有用户看到了某个特定的恶意广告，广告代码才会触发真正的行为——收集浏览数据、注入广告、篡改购物链接。这个"睡到看见广告才醒"的设计，专门绕开"装上先观察几天"这类静态审核与沙箱。处置建议很直接：按扩展 ID 盘点而不是按名字，重点清查那些声称能比价、返利、看视频的插件。

8. Sansec：新的 Magento 恶意家族，装进了近 1,000 家店铺

Sansec 发现一个新的恶意软件家族，已在接近 1,000 家线上商店落地。它和 9 月的 StyleSmuggler（CVE-2026-75650，本刊 10-14 期报过同引擎的 BlockStrap）不是同一件事，但指向同一条规律：电商结账链路上的模板引擎一旦能把数据当指令处理，落地页本身就是入口。店铺方要做的三件事：查 pub/media 与 var/ 下近期新增的可执行文件、比对后台管理员列表有无新增、把支付页面的出站连接做一次基线比对。

9. Aokigahara 信息窃取器：改名之后，把 AI 工具加进了采集清单

Check Point 在地下市场发现一款新的信息窃取器 Aokigahara，它是旧家族 Kamidere / Stygian 的改名重制版。这一版最值得注意的变化是新增了对 AI 相关服务与工具的凭据采集。这条趋势比单个家族重要：模型 API key 现在和浏览器保存的密码、钱包助记词放在同一张采购清单上，而很多团队的 key 从来没有过期策略、没有用量告警、也没有绑定来源限制。

10. Web Hole：聊天代理默认读搜索结果第一条，而那条域名可能刚被人买下

Air Security 提出一种叫 Web Hole 的手法：很多 AI 聊天代理在回答时会默认去拉搜索结果的靠前条目，而搜索结果顶部存在若干已过期、可被任意注册的域名。买下它们，就能在代理"引用来源"的路径上放恶意提示与内容。它不需要攻破模型，只需要占据模型会去读的那个位置。防守侧的动作有两个：给代理的联网检索加域名白名单，以及对"回答里出现你没听说过的来源域名"做人工抽检。

11. GhostShares：Muse 的私聊被生成了公开 URL，功能已下架

Meta 关闭了 Muse AI 私密对话的分享能力。原因是这个功能会为对话生成公开可访问的 URL，任何人只要拿到或猜到链接就能打开，并被搜索引擎与爬虫抓走。ChatGPT 与 Grok 去年出现过同一类问题，说明这不是某一家实现失误，而是"分享"这个动作在 AI 产品里的默认危险度被系统性低估：一段对话里可能同时有代码、客户名单和内部决策。给用户的建议只有一句：不要用生成的链接分享任何你不敢发在公开群里的对话。

12. Crow CVE-2026-116011（7.5）：一段深层嵌套 JSON 打空 worker 线程栈

C++ 微型 Web 框架 Crow 1.3.4 之前的版本，可被一个未认证的远程请求打挂：请求体里放深度嵌套的 JSON，递归解析会把 worker 线程栈耗尽，随后所有连接一起掉。公开 PoC 在 10-25 首次被记录。修复版本 1.3.4。这类漏洞的杀伤力取决于部署形态：单 worker 直接全站不可用，多 worker 还留着余量。Crow 常被嵌进小型网关与内部服务里，资产清单里未必认得出来，值得顺手查一遍 crow_all.h 的版本宏。

13. YesWiki CVE-2026-116207（9.1）：转义函数用错了地方

这枚的教训比分数值钱。YesWiki 从未认证的 HTTP 参数里取字段名，用反引号包起来当 SQL 标识符，然后用 mysqli_real_escape_string 转义内容——而这个函数只管字符串字面量里的引号、反斜杠、换行与 NUL，不管反引号。于是攻击者给一个反引号就能闭合标识符、写进 SQL、再开一个新的标识符。向量是 C:H/I:N/A:H，完整性无影响：这是只读加拒绝服务的注入，能从 JSON 响应里直接回显 yeswiki_users 的口令哈希，或用 SLEEP() 挂住数据库线程。按"能改数据"去找痕迹会一无所获。修 4.7.0 与 5.0.0-alpha4；这是 2026 年针对 YesWiki 的第七个 SQL 注入类公告，其中五个免登录。

14. Oracle CVE-2026-114820（9.1）：JSSE 移除 eMudhra 相关根证书

十月 CPU 里这枚正式编号覆盖全部在支持期的 Java SE（8u511、11.0.33、17.0.21、21.0.13、25.0.5、27.0.1）与 GraalVM for JDK 17.0.21 / 21.0.13、GraalVM EE 21.3.20，CWE-327，向量 AV:N/AC:L/PR:N/UI:N/C:H/I:H/A:N，公开 PoC 于 10-25 首次被记录，未进 KEV。处理方式就是应用十月 CPU；跑在 WebLogic、JBoss、Tomcat 或厂商自带 JRE 里的，要另查厂商自己的公告节奏，别只看 Oracle 那一份。前情提示：本刊 10-21 期报过 eMudhra 八张中间 CA 私钥的问题、10-24 期报过同一批证书的 CVE-2026-91403，本轮这枚是同一根因在 CPU 里的正式编号，不是新事件。

15. 今天到期的两条：Arista VCO 与 Collabora CODE

CISA 在 10-23 把 CVE-2026-114625（Arista VeloCloud Orchestrator，SQL 注入，9.9）与 CVE-2026-110447（Collabora Online 内置 CODE Server，OS 命令注入，9.2）加入 KEV，联邦修复期限就是今天，10-26，并按 BOD 26-04 要求做取证分诊。两枚本刊分别在 10-23 期与 10-17 期详报过，这里只提醒期限：VCO 升 5.2.3.18 / 6.1.3.10 / 6.4.2.12，Collabora 修在 26.4.303，且禁用不等于修好，需升级或移除。
