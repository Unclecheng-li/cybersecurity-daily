傲梅备份更新服务器被投毒：每次只开 5–10 分钟，却留下长期后门

信任链在往下沉：更新通道、管理面、宿主内核——今天四起事件分别击穿了这四层，而补丁一律不负责"退场"。

1 严重

AOMEI Backupper 更新服务器投毒 — 「修补服务器」并不等于「清理终端」

2026-10-16 披露 · GTIG / Mandiant / ManageEngine 11 国 · 供应链入侵

Google Threat Intelligence Group（GTIG）、Mandiant 与 ManageEngine 威胁分析实验室于 2026-10-16 同步披露：傲梅（AOMEI）Backupper 的更新服务器在 2026 年春末至 7 月间被攻击者短暂控制，在 3 个 5–10 分钟的窗口内向正在轮询更新的 Windows 设备下发了带后门的安装包。三个已确认窗口合计仅约 21 分钟，首尾相隔 53 天；受影响组织分布在 11 个国家，集中在 IT 服务、电信与高等教育。

问题的根因不在传输加密，而在产品本身不校验更新包的密码学签名——文件是从官方服务器、走 HTTPS、由程序按正常更新流程主动拉取的，因此"官方渠道 + HTTPS"这两道看似充足的信任假设同时失效。

关键事实：

  • 单点可断：SHINYROAD 仅连接一个硬编码地址、无备用，封锁该地址即可切断控制通道
  • 载荷链：下载器 CROSSROAD → 解包到本地 Radmin 目录 → 建每 3 小时计划任务 → 自删；捆绑正版签名 Radmin 做侧加载 → SHINYROAD（远程 shell + 按指令下载执行）；后续再叠加伪装成 Nitro PDF 的 Adaptix C2
  • 无代码泄露：7-20 窗口另篡改通知配置文件，打开不可见的 1 像素弹窗经 WebDAV 指向攻击者服务器，Windows 渲染时自动回送当前用户的 NetNTLMv2 响应，即使后门被拦也可能已泄露凭据
  • 厂商初次说法被推翻：傲梅先称"传输中被拦截篡改"，实验室不认可——两台设备分处不同国家与网络、均从官方服务器经 HTTPS 拉取；7 月中旬实验室实时捕获篡改窗口，证实由服务器端下发
  • 检测陷阱：下载器落盘后把本地更新文件恢复为正常内容，窗口过后服务器下发的又都是干净文件——曾有分析人员把真实告警误判为误报

值得关注的原因：

  • 傲梅已整改服务器，但窗口期内拉到过恶意包的机器仍是失陷状态，厂商侧动作无法回溯清除已投递的植入体
  • 拿的不是 0day，而是一个设计选择：几分钟的替换把"样本稳定可查"这一传统 IOC 前提直接打掉；GTIG 称这是其遇到的第一个专门利用极短窗口 + 正常更新流程的 Windows 供应链入侵
  • 排查必须跨 4 个月：保留程序自身缓存目录中的更新文件、回查告警发生当时的网络日志，而不是现在打开厂商下载页（那一刻早已是正品）
  • 未披露受影响版本，实验室分析样本为 8.3.0；当前 8.5.0（10-09）的更新日志未体现校验机制变更
更新服务器写权限被夺 5–10分钟窗口换包 CROSSROAD 解包 签名 Radmin 侧加载 SHINYROAD 长期驻留
2 高危

PEERSTITCH — 寄生在 FortiOS 两个守护进程之间的内存植入体

Unit 42 · CL-STA-0954 / UNC5820 中危漏洞 · 高危后果

Unit 42（Daniel Gott、Shawn Westfall）披露一起起始于 2024 年 9 月的长期入侵，目标是一家电信行业托管服务商。入口是 FortiManager 的 FortiJump（CVE-2024-47575）；攻击者取走了包含 500 多台托管 FortiGate 运行配置的归档——序列号、管理关系、拓扑、路由、接口、加密的管理员与 VPN 凭据，以及证书与私钥。随后用 CVE-2025-61624（FortiOS 命令行解释器路径穿越，CVSS 5.4 / 厂商记 6.0，2026-04 已修）投放 PEERSTITCH。

技术要点：

  • 64 位 Linux ARM64 可执行体，多组件下发（落地文件含 pM.js、a.wasm、lldprx）
  • lldprx 用 ptrace attach 到合法的 /bin/miglogd（日志）与 /bin/iked（VPN），分配可执行内存并重定向执行流
  • miglogd 钩子识别标记（TCP 8550、169.254.0.1）→ 传会话标识给 iked → 标记会话走替代路径，跳过 FortiOS 默认校验
  • 无落盘、无监听端口、无主动外联，通信寄生在合法进程流量中
  • 附带手法：用 Apache mod_md 搭 SSH 反连；关日志、清崩溃记录、断遥测、删越权管理员

为什么值得记住："中危"评分的前置条件是高权限，而攻击者从 FortiManager 拿到的正是这个前置条件；被窃的配置、证书、私钥在设备升到最新版后依然有效。CISA 已于 10-16 收录该 CVE。猎捕方向要换：查 miglogd / iked 内存中的匿名 16KB RWX 区域、守护进程异常崩溃、遥测缺口；日志务必外送到设备之外。

3 严重

PwnEscape CVE-2026-99999 — 一个包的校验和写错位置就能读宿主内核

CVSS 9.3 · Linux 网络栈 客机 → 宿主 · 无在野

Linux 网络栈的延迟校验和处理存在缺陷：csum_start / csum_offset 由客机提供，而 skb_checksum_help() 在 IPv4 头已被解析并信任之后才写校验和；构造的元数据让这次写入落进已通过校验的 IPv4 头——首字节 0x45 变 0x4f，IHL 宣称头长 60 字节。分片时 ip_do_fragment() 按 60 字节读取，多出的 32 字节宿主内存被当作 IP options 复制进包发回攻击者。

验证程度必须分清：宿主内存泄露已在 Vercel 生产沙箱持续复现（每包约 32 字节）；宿主崩溃两个包即可；宿主 root 代码执行仅在实验室（研究者自建 KVM / Firecracker，4 次冷启动取得定向 64 字节内核写）。

来龙去脉：Vercel 8-18 发起 100 万美元沙箱逃逸挑战，pwn.ai 的 Paulos Yibelo 第 3 天提交报告——虽未逃出 Vercel 沙箱，却挖到更底层的东西，1,285 份提交中唯一一枚 critical。pwn.ai 称其 AI 辅助系统 Omega-Pwn 用 3 天、不到 700 美元 API 费找到该缺陷。

修复提交 6785011f8b16（Red Hat 的 Michael S. Tsirkin），5 处 / 6 文件加防护，作者自评"纵深防御"，入口完整校验仍待补。已修复：5.10.272 / 5.15.223 / 6.1.190 / 6.6.159 / 6.12.113 / 6.18.57 / 7.2.11（Debian 侧 DSA-6568-1）。只补客机完全无效，必须升级宿主内核并重启；AWS 称 EC2 / Lambda / Fargate 不受影响，自建 KVM 与中小云厂商需自行取证确认。

4 高危

OpenBSD 37 年老洞打出 root：1988 年的一个 short，加一次越界写

Calif / Andrew Griffiths · 公开 PoC 无 CVE · 绕 KARL/SMAP/SMEP

Calif（MAD Bugs 项目）于 2026-10-16 公开在 OpenBSD 7.9 上本地提权到 root 的完整 PoC。链条入口可追溯到 1988 年原始 BSD 源码：共享内存挂接计数器 shm_nattch 定义为有符号 16 位 short（上限 32,767），OpenBSD 一直沿用未加宽。映射 127 个 SysV 共享内存段、munmap 后再 fork 259 个进程，可把计数推过上限并回绕到 -32,643，引发竞态导致的内核 use-after-free；叠加一处条件性越界写，即可在没有任何信息泄露的情况下拿到 root。

绕过 KARL 的原因：KARL 只重链接内核镜像、随机化函数与数据地址，但内核内存分配器仍是确定性的——启动分配器与 best-fit 分配器都缺基址随机化，因此 lo0、enc0 的 ioctl 处理函数指针在同一硬件上跨重启落在同一位置。

修复：整数溢出见 errata 018（9-14 发布，当初归类为可靠性修复，7.8 亦覆盖）；引用计数 UAF 见 errata 026（9-30，安全修复）。均经 syspatch 提供（amd64 / i386 / arm64），需重启生效。加固建议：内核双链表 safe-unlinking、PTE 自引用映射随机化（320 + (rand & 127) 选 PML4 slot）、分配器随机化。

要点：37 年间它跨过了无数轮审计与模糊测试，因为没人会怀疑一个"计数器"的宽度；更麻烦的是入口漏洞最初按可靠性修复发布，只订阅安全公告的团队会漏掉一半。目前无 CVE、无在野，但 OpenBSD 常用于防火墙、VPN 网关与网络设备，本地提权的边际价值很高。

5 严重

Collabora CVE-2026-110447 — 补丁 9-09 就位、CVE 10-14 才发，一个月空窗被打成后门

CVSS v4 9.2 · CWE-78 Nextcloud 未认证 RCE

Nextcloud 的 Collabora Online – Built-in CODE Server 应用（richdocumentscode，低于 26.4.303）存在命令注入：proxy.php 处理 remote_font_config.url 时未正确转义即拼进 bash 命令，$()、${IFS}、base64 管道喂 sh 均可触发，无需认证、无需交互。唯一前置条件是内置 CODE server 处于停止状态（重启、升级或崩溃之后）——运维上再正常不过的一个瞬间。

时间线才是重点：

  • 9-09 修复提交入仓 → 9-11 版本 26.4.303 发布，同日已有管理员在 issue 里报告攻击
  • 10-03 社区发布紧急升级提醒，仍无 CVE 编号
  • 10-14 安全公告与 CVE 正式发布；10-15 Collabora 博客敦促升级

Collabora 把延迟归因于 GitHub 的 CVE 处理积压（AI 生成的安全报告激增），一个 CVE 从"约一天"变成"数周"。Second Security 的数据更硬：修复公开到 CVE 发布的中位间隔，从 1 月的 5.1 天涨到 8 月的 39 天，而公开 diff 本身就是利用代码的入场券。

处置：升级至 26.4.303+ 或彻底移除，仅禁用不够（proxy.php 不经 Nextcloud 核心安全框架，是绕过平台主防线的盲区）；在应用目录找 shx*.php，在 Web 日志查携带 %2e%2e、%24%28、IFS 的 proxy.php 请求；命中即按失陷处置，轮换数据库口令、config.php secret、应用专用密码。攻击者搜的是 *.kdbx、wallet.dat、keystore.json 与 1Password / Bitwarden 目录。

独立部署的 Collabora Online、Docker 镜像、RPM/DEB 包与 Nextcloud All-in-One 不受影响。

速览区

6. BeyondTrust CVE-2026-102764 入 KEV，联邦大限 10-19（NVD 9.3）

Remote Support 内部消息组件来源校验不当，可对设备执行文件操作并写入 webshell 提权。修复不是换版本号，而是打 BT26-05-RS（适用 24.3.1–26.2.3，更低版本须先升级；PRA 有独立构建），SaaS 已于 10-09 修完。后渗透手法值得记住：SAWFLY webshell（mangoapi.php，参数不对一律 404）、/bin/sh 复制成 /usr/bin/dbus-authd 置 SUID、向 sudoers 模板注入免密 sudo（重启与配置重置都存活）、改 HAProxy 把 WebSocket 路径转发到本机 SOCKS。设备文件系统客户无法审计，暴露期内未打补丁者按已失陷处置；轮换凭据务必在隔离之后。

7. Atlassian CVE-2026-21589 确认在野，八款 Data Center 产品，大限 10-18

路径穿越致任意文件访问，未认证即可读取 Web 应用根目录文件并越出根目录访问受限路径；覆盖 Bamboo、Bitbucket、Confluence、Crowd Data Center、Crucible、Fisheye、Jira Software / Jira Service Management Data Center 的所有版本。缓解是攻击者须已知确切文件名、无法列目录——但 WEB-INF 下的配置与密钥文件名是公开知识，这条缓解的实际价值有限。CISA 10-15/16 确认在野并收录 KEV；云版已修。

8. F5 与 Juniper 同日大补：NGINX 11 个、Junos 150 余个

F5 修复 11 个 NGINX 缺陷，三枚 critical：CVE-2026-15176 与 CVE-2026-93479 可由未认证攻击者用特制 HTTP 请求触发缓冲区溢出，ASLR 关闭或可绕过时升至 RCE；CVE-2026-97205 同样可致内存破坏。Juniper 发布 17 份公告覆盖 150 余个缺陷（另有 JCNR 4 个），约两打 critical，可致 root 级执行与整机接管。两家均称未发现在野利用，但"未认证 + ASLR 关闭"常见于容器与嵌入式固件，实际风险高于评分。

9. Arch 用户仓库出现假 yay / paru 包，安装脚本以 root 拉远程 shell

用户 marchos1as 上传与流行 AUR 助手同名的抢注包，安装脚本在构建阶段以 root 执行远程 shell 脚本。社区 10-13 举报，AUR 团队当天封号并删包。凡安装过应直接按失陷处置——PKGBUILD 在 makepkg 阶段以当前用户（通常是可 sudo 的账号）运行，等脚本跑到 root 段落时已无沙箱。建议把"AUR 包名与上游仓库一致性校验"纳入构建准入。

10. Semperis：四分之一勒索案件伴随暴力威胁，53% 真的兑现

过去 12 个月统计：约 25% 的勒索攻击包含心理胁迫与人身暴力威胁；这些案件中 53% 的受害者表示攻击者确实兑现，24% 遭遇 swatting（报假警引特警上门），25% 因此寻求心理或医疗帮助，24% 为家属雇了私人安保。勒索的经济模型正从"加密数据"转向"胁迫人身"，谈判、执法对接与员工保护需要提前写进 IR 预案，而非事发补课。

11. Wavlink 两枚满分 CVE 且已公开利用：api.cgi 登录处理是入口

CVE-2026-110957：api.cgi 登录处理把 REMOTE_ADDR 直接拼进系统命令，远程未认证即可注入；CVE-2026-110958：同文件堆缓冲区溢出。两者 CVSS 均 10.0，NVD 明确记录已有公开利用代码。修复固件 2026-09-24-841a51c6d5 把登录脚本改为参数数组调用并校验客户端地址——属于正确修法。处置：只从官网取固件、关闭 WAN 侧管理、升级后改口令并复查 DNS / 端口转发 / 账号。
