1 头条事件

AhsayCBS 双零日链（CVE-2026-105133 + 105134）：未认证 SYSTEM 级 RCE，JSP webshell 与 XMRig 挖矿已落地（头条）

AhsayCBS 备份服务器（MSP / 系统集成商集中管理）· 10-04 披露 · 10-07 23:20:15 UTC 起在野 · Huntress / Field Effect / BleepingComputer 105133 认证绕过 CVSS 4.0 = 5.5 · 105134 命令注入 CVSS 3.1 = 10.0 · 24h 内 5 家组织被攻陷 · 10.3.4 仍被认定受影响

安全厂商 Huntress 记录：自 2026-10-07 23:20:15 UTC 起，攻击者把两枚刚披露（10-04）的 AhsayCBS 漏洞串成完整攻击链，对暴露在互联网上的备份服务器实现以 NT AUTHORITY\SYSTEM 权限执行的未认证远程代码执行。次日已有至少五家组织被攻陷；Field Effect 于 10-09 在情报报告中确认该活动，BleepingComputer 报道厂商未回应其修复计划。

两枚 CVE，一弱一强：CVE-2026-105133 是 checkSysPwd 函数中的认证不当（com/ahsay/obs/api/ApiStructsAction.java），CVSS v4.0 仅 5.5（Medium）——看着不起眼的"半枚"；CVE-2026-105134 是复制接收端 POST /rps/api/json/UpdateReceivers.do 的操作系统命令注入，CVSS 3.1 高达 10.0（v4.0 为 9.3 / Critical）。API 中随机 token 可冒充有效凭据完成认证绕过，攻击者据此配置一个恶意的 replication receiver，把 JSP webshell 落进 CBS 应用自身对外提供服务的目录里。两枚记录在 NVD 状态均为 Deferred，PoC 在披露时已公开。

无补丁 + 版本存疑：受影响版本记录为 10.3.0 – 10.3.2，厂商称 10.3.4.0（2026-08-04 发布）已修复两处；但 Huntress 在 10-08 进一步核查后指出：10.3.4 同样受影响。截至 10-10 仍无官方补丁。在版本分歧澄清之前，无论哪个版本都应先限制管理界面的访问。

落地的东西（后渗透链路）：Huntress 从 cbssvcX64.exe 派生的可疑子进程切入（webshell 命令直接表现为该服务的子进程，是可用检测锚点），还原出：侦察 → JSP webshell → XMRig（Monero）矿机。矿机文件 edge.exe 从阿里云对象存储暂存，同批还有改名的 NSSM 持久化工具 msedge.exe，最终被装成一个名为 MicrosoftEdgeUpdateSvc 的 Windows 服务——与合法 Edge 更新器只差一个字母——以 SYSTEM 运行。挖矿流量指向 Kryptex 矿池（xmr.kryptex[.]network:8029，pool user krxYMRN97D/creativejs）。

两处值得单独记的细节：其一，脚本 Taskgmr.ps1（Huntress 从代码注释判断疑似由 AI 辅助生成）会持续监视任务管理器——窗口一打开就暂停挖矿、关闭后自动重启，并在本地时间 18:00 或夜间保持开启超过一小时时直接杀掉任务管理器；其二，攻击者用 certutil.exe 投放已知脆弱的驱动 WinRing0x64.sys——这次不是为了致盲 EDR，而是让矿机拿到内核级硬件访问以最大化算力。

为何值得关注：备份服务器是攻击者最想站上去的那台机器。AhsayCBS 是备份操作的集中管理点——用户、策略、存储位置、复制关系都在一处——且高度集中在 MSP 与系统集成商手里，一次部署管理多家客户的备份。拿到管理服务器的 SYSTEM，意味着凭据、存储库与管理员功能全部暴露，并通向连接的存储、域服务和特权服务账号。更要紧的是，它恰好是勒索事件后用于恢复的那套基础设施：今天的载荷只是矿机，但已演示出的访问能力（webshell、SYSTEM 服务、次级后门）可以是下一个攻击者想要的任何东西。

处置：立即限制 AhsayCBS 管理界面的访问（IP 白名单或强制 VPN）；尽可能升级到 10.3.4.0；已确认失陷的服务器必须从可信备份整机重装——Huntress 明确指出，升级无法清除 webshell 与恶意配置，次级后门会比软件更新活得更久。

2 未认证 RCE

Gotenberg CVE-2026-42589（CVSS 9.8）：未鉴权元数据键注入，一条 HTTP 请求拿到容器内 RCE

Gotenberg（Docker PDF/HTML 转换 API）· 修复 8.31.0 · CWE-78 / CWE-77 · Nuclei 模板已发布 CVE-2026-42589 CVSS 3.1 = 9.8 · 影响 ≤ 8.30.1（8.30.1 修复不彻底）· 响应伪装为正常 PDF

研究人员公开了被广泛依赖的 Docker 文档转换服务 Gotenberg 的一处未认证命令注入：只要单条 HTTP 请求，就能以容器用户身份执行任意命令，而响应看起来只是一次正常的 PDF 转换。

  • 漏洞与端点：CVE-2026-42589，CVSS 9.8（Critical），CWE-78（操作系统命令注入）/ CWE-77（参数注入）。出问题的端点是 /forms/pdfengines/metadata/write，它未做鉴权，并把用户可控的 JSON metadata key 直接传给 ExifTool
  • 利用手法（参数走私 → Perl eval）：攻击者在 metadata 的 key 里塞入换行符 \n，用来切断 ExifTool 的 stdin 输入流，随后走私一个 -if 参数——形如 {"Title\n-if\nsystem('sleep 6')||1\n-Comment":"x"}——-if 会把后续内容当作 Perl 表达式求值，于是 system('…') 被触发，单条 HTTP 请求即完成 RCE。最阴的地方在于：返回的是干净的 200 加一份合法 PDF，监控侧只看到"一次成功的转换"
  • 影响与修复：受影响版本 ≤ 8.30.1，官方修复 8.31.0；且 8.30.1 的修复并不彻底、仍可绕过。同一条利用链还有"姐妹"编号 CVE-2026-40281（CVSS 10.0）。Nuclei 模板已经发布（作者 fineman999），可直接用于批量探测

为何值得关注：Gotenberg 在很多技术栈里"安静地"存在——Paperless-ngx、Nextcloud、Documenso，以及大量企业内部的发票/合同文档流水线都直接调用它的 HTTP API 做格式转换。它一旦暴露在公网、或被内网穿透，攻击面就直接顶到 RCE；而"未鉴权 + 返回正常"的组合，让这类漏洞既好打又难发现。非必要不要暴露在公网；无法立即升级时，应在网关层限制该端点的可达性。

4 代码注入双 9.8

openapi-typescript-codegen CVE-2026-108551 + Floci CVE-2026-108598：一条污染构建流水线，一条打穿云模拟器

2026-10-10 同日披露 · 均 CWE-94 · 均无公开利用、未入 CISA KEV 108551 openapi-typescript-codegen ≤ 0.31.0 · 108598 Floci 1.1.0–2.2.0 · 均 CVSS 3.1 = 9.8 / v4.0 = 9.3

10-10 同日披露了两枚 CVSS 3.1 = 9.8（v4.0 均为 9.3）的代码注入漏洞，同属 CWE-94，均无公开利用、未入 CISA KEV——但触发条件都很"日常"。

  • CVE-2026-108551 —— openapi-typescript-codegen（≤ 0.31.0）：把不可信 OpenAPI 文档变成生成客户端里的 JS。该代码生成器在 Handlebars 模板中，把未转义的值插进了单引号字符串字面量；攻击者只要能控制 OpenAPI 文档，就能通过 path keys、参数名、servers[0].url、info.version 等字段注入 JavaScript。载荷会在生成的客户端被 import 或调用其服务方法时执行，从而污染整条构建流水线的下游——浏览器应用、Node 服务，以及后续构建步骤的每一个消费方。修复版本 > 0.31.0 待定
  • CVE-2026-108598 —— Floci（1.1.0 之前 ~ 2.2.0）：云模拟器里的未认证 OS 命令执行。Floci 是一款类 LocalStack 的 AWS API Gateway 模拟器。其 VtlTemplateEngine 允许未认证攻击者创建一个带 MOCK 集成的 REST API，其 Velocity 模板可借 $util 反射触达 Runtime 或 ProcessBuilder，最终在 Floci 所在 JVM 内执行操作系统命令。修复版本 2.2.0

为何值得关注：这两枚"日常工具链"漏洞指向同一句话——"你信任的输入格式，本身就是一条代码通道"。OpenAPI 规范本该是描述性的数据，却在模板渲染中变成了可执行脚本；Velocity 模板本用于 API 编排，却在模拟器里成了反射跳板。两者机制不同、结局同为 CWE-94，且分属构建期与运行期：一个是"别人给的规范污染你的产物"，一个是"任何能访问实例的人拿到你的主机"。"无公开利用、未入 KEV"不该成为延后修补的理由——这两类组件通常藏在内部，而内部恰恰是补丁最容易被无限期推迟的地方。

6. Citrix NetScaler CVE-2026-88771 / 88772（+ 88773–88778）簇入选 CISA KEV：超 5 万设备，9-24 起在野

CISA 把 Citrix NetScaler ADC / Gateway 的一组漏洞并入 KEV 目录，其中 CVE-2026-88771（命令执行，9.5） 与 CVE-2026-88772（RCE / DoS，9.5，默认启用 DTLS 时触发） 最受关注，同批还有 88773–88778（官方公告 CTX697096）。威胁行为者以预认证命令利用，潜在受影响设备超 50,000 台，攻击尝试自 2026-09-24 起持续被观测。攻击者还被发现篡改 Web 服务器文件植入恶意代码、用 webshell 维持持久访问。这与近期"边缘设备/网关高危补丁连发"的态势一致——对外暴露的 VPN/网关是初始访问的高频入口，版本核对与暴露面收敛要同步做。

7. OpenSSH 10.6（10-06）移除 LZ77 压缩字典，默认启用抗量子混合签名

OpenSSH 10.6 于 10-06 发布，做了一件"减法安全"的典型事：直接移除 SSH 压缩所用的 LZ77 字典编码器，以斩断一类选择明文侧信道——当攻击者可控数据与密文/秘密共享同一压缩上下文时，压缩后长度差异会泄露秘密信息（即 CRIME / BREACH 在 SSH 上的同类问题，该问题自 2002 年即已知）。同时：默认启用混合后量子签名算法 ssh-mldsa44-ed25519；新增 WarnWeakCrypto 标记使用非抗量子密钥交换的连接；命令行传入的用户名不再允许 $ 与 \（降低 ProxyCommand / Match exec 场景下的 Shell 注入）；SFTP 收紧路径校验。项目还表示将转向更频繁的发布节奏。值得一提的是，相关 PoC 由 Claude 等 AI 编码助手辅助构建——AI 驱动的漏洞发现正把"从漏洞到利用"的周期从数年压缩到数天。

8. Cisco SSM On-Prem CVE-2026-20328（9.1）密码重置漏洞可接管管理员账户

Cisco Smart Software Manager On-Prem（SSM On-Prem）披露 CVE-2026-20328（CVSS 9.1）：一处密码重置流程缺陷可被利用来接管管理员账户。同期另一枚 CVE-2026-76482（CVSS 10.0） 由 Cisco 内部安全审查发现并随加固版本一并修复——厂商虽定性为"主动加固"，但满分本身说明该缺陷很可能涉及认证绕过或 RCE，且"公告本身会加速攻击者对该修复的逆向研究"。运行 SSM On-Prem 的环境应尽快升级。

9. 丹麦中央人口登记（CPR）因弱口令"123456"发生大规模泄露

丹麦中央人口登记系统（CPR）在一处缺陷中发生大规模泄露，报道指其弱管理员口令被暴露——其中出现的口令是 123456。这一案例的警示不在于技术复杂度，而在于关键公共登记系统的"最后一公里"竟停在一个默认弱口令上：再强的架构也拦不住一个可猜的管理员密码。对所有拥有"高价值中央系统"的组织，特权账号的强口令 + MFA + 轮换是成本最低、收益最高的那道闸。

10. Silent Ransom Group 无恶意软件社工勒索 2.07 亿美元；MonsterCloud 老板因私下代付赎金被诉

Silent Ransom Group 被指不使用任何恶意软件，纯靠社会工程（冒充、电话社工）实施勒索，累计勒索金额达 2.07 亿美元——这再次说明勒索的"杠杆"是数据与信任，而非加密本身。另一侧是"勒索生态的反噬"：MonsterCloud 的老板因私下替客户支付赎金又赚取差价（涉及 1,100 万美元解密加价）被以欺诈罪名起诉；另有一名美国网络安全高管因 1,100 万美元解密骗局被起诉。这些案件共同暴露了"勒索谈判/解密中介"这条灰产带：受害者最无助的时候，正是最容易被自己请来的"救兵"二次收割的时候。

11. 安天 10-11 通告：GnuTLS / Linux 内核 rxe+xfrm / Splunk 本地提权

安天"网络行为检测能力升级通告（2026-10-11）"列出本期活跃漏洞：GnuTLS 主机名验证绕过（CVE-2026-88647）、IBM DataPower Gateway 跨站脚本（CVE-2026-14990）、Linux 内核 rxe 整数溢出（CVE-2026-98365）、Linux 内核 xfrm 释放后重用（CVE-2026-98370）、Splunk Enterprise 本地权限提升（CVE-2026-76266）。其中内核两枚与 Splunk 本提权值得本地提权（LPE）方向的读者重点关注；Splunk 一侧此前还修复了 Patroni REST API 未认证命令执行（CVE-2026-76268，CVSS 9.8） 等一批问题，SIEM 平台自身的漏洞会直接影响组织的检测与响应能力，不宜积压。
