守门的人自己先倒下：一台 WAF 的统计图表，成了整台服务器的 root

今天最值得看的三件事，都不是"某个业务系统出了洞"——被穿透的是一台主机式 WAF、一条被版本锁死的依赖链、一家海运软件商的数据库。防线自己成了突破口，后面就没有第二道门了。

1 严重

SiteGuard Server Edition 命令注入 CVE-2026-106931 — 默认开启的统计功能，以 root 执行任意命令，已在野

2026-10-18 JPCERT/CC 确认在野 · EG Secure Solutions CVSS 4.0 8.5 / 3.0 7.8

日本厂商 EG Secure Solutions（e-guardian） 的主机式 Web 应用防火墙 SiteGuard Server Edition 存在 OS 命令注入，位置在统计功能——那个用来汇总"拦了多少、放了多少"的图表模块，默认开启。厂商与日本 JPCERT/CC 已共同确认：漏洞正在被利用（JVN#88474777）。两边都没有披露攻击者身份、受害组织和影响规模。

关键事实：

  • 后果是最高权限：Linux 上拿到 root，Windows 上拿到 NT AUTHORITY\SYSTEM。不是一个可以被绕过的过滤器，而是源站主机本身
  • 受影响区间很长：Apache httpd / Nginx / IIS 版（FreeBSD 除外）2.20 及以后、8.00 Update 5 之前全部受影响；FreeBSD 上的 Apache / Nginx 版为 2.20 及以后、7.00 Update 6 之前。唯一例外是 IIS 版 3.10 至 4.00 Update 4（含）
  • 公告发出时攻击已在跑：厂商早在 9-29 就通知了有直签支持合同的客户，公开公告是 10-14，JPCERT/CC 确认在野是 10-18。走经销商、没有支持合同的用户，真实暴露窗口早于自己读到公告那天
  • 补丁会抹掉证据：厂商明确警告升级会覆盖统计处理文件，痕迹一起消失。正确顺序是先导出诊断包再打补丁：Web 管理界面 → Diagnostic information → Download diagnostic information，并保存到设备之外
  • 连 EOL 版本都给补丁：无法升级的可安装替换统计处理文件的补丁，覆盖已停止支持的版本。厂商为 EOL 破例，本身就是对危害的判断

值得关注的原因：

  • 主机式 WAF 的位置决定了它的破坏力。它通常与应用装在同一台机器上才能解密流量做检测。WAF 进程一旦被拿到命令执行，防火墙、数据库、应用在同一台机器上，一个洞全塌；而攻击者还顺手获得了这台机器的完整流量视图
  • 为可观测性写的代码，成了执行入口。这类"运维看图表"的模块长期不在安全评审视野里，却默认开启、几乎每个部署都在跑
  • 评分与真实风险脱节。JVN 给的是 CVSS 4.0 8.5、CVSS 3.0 7.8，厂商自己标 critical。在边界设备上以 root 执行命令，这个分数明显偏保守
  • 别搞混产品线：SiteGuard 还有一个 WordPress 插件（约 50 万装机量），常被混为一谈。本次公告只覆盖 Server Edition。厂商宣称整体保护超过 150 万个站点
构造统计接口请求 参数未转义进命令 WAF 进程执行 root / SYSTEM 同机应用与数据库直取
2 高危

Rapid7 放出 Zimbra 五个漏洞的 PoC — 一个普通账号，读写冒充全通，还有两枚至今无补丁

2026-10-14 披露 · Jonah Burgess / Rapid7 5 枚 CVE · 2 枚无修复

Rapid7 一次性披露 Zimbra Collaboration Suite（ZCS）五个漏洞，每一枚都附公开 PoC 脚本，系列文章《From One Account to Every Mailbox》Part 1。测试环境为 ZCS 10.1.16 Network Edition on Ubuntu 22.04。Rapid7 称这轮评估总共报了 80 多个漏洞，后面还有。

五个洞分别做什么：

  • CVE-2026-10631（6.5，修 10.1.20） — EWS 的 FindItem 信任复合 folder ID 里的 owner ID。开过 EWS 的普通用户可读他人收件箱、已发送、草稿、联系人、日历，含原始 MIME 与附件，不需要共享或委派；目标自己不必开 EWS，跨集群服务器也生效。NVD 标记 10.1.0–10.1.19
  • CVE-2026-50055（6.5，修 10.1.20） — 管理员关掉转发后，Zimbra 只阻断 Sieve 的 redirect，notify 照样把邮件头与正文文本发到外部地址，规则还持久存在。Modern Filters 界面看不到，Classic 只显示规则名不显示目标
  • CVE-2026-73571（8.3，修 10.1.17；NVD 3.1 只给 4.3） — SaveDraftRequest 的委托发送路径让任何已认证用户以同服务器另一账号名义发信，不需要 send-as 权限，邮件走正常外发通道并落进受害者的"已发送"
  • CVE-2026-93635（5.3，无修复） — 使用外部 LDAP search-filter 认证并开启 lazy provisioning 的域，登录处未转义的通配符变成目录用户的密码预言机；默认本地认证不受影响
  • CVE-2026-93637（3.7，无修复） — 失败的 GraphQL 认证不计入每 IP 失败计数，alias 还能把大批猜测塞进一个请求。Rapid7 实测 10,000 个候选、每请求 100 个、不到两分钟跑完；与 93635 组合可同时绕开两套锁定计数

为什么值得关注：Zimbra 把"账号"当安全边界，这五个洞全在这条边界上打洞——一个普通账号能读、能冒充、能外带，两枚无补丁的洞负责让外部人先拿到那第一个账号。单看分数都很低，但 CVSS 算的是单个缺陷，攻击者算的是组合。邮件又是密码重置、合同确认、财务指令的凭据载体，这条链的实际杀伤远高于分数。

处置：先查 EWS 是否对外可用；直接读数据库里的 Sieve 脚本而不是看界面；把 10.1.20 设为底线版本；对 93635 / 93637 用网络层压掉登录接口的暴露面。

SAP 十月补丁日四枚严重 — 最高的 10.0 不在 ABAP，在一个 Python 库，而且它八月就修好了

2026-10-13 补丁日 · 22 项 · 4 枚 Critical CVE-2026-89111 · 10.0

SAP 十月安全补丁日共 22 项（16 条新 note、4 条 GitHub 安全公告、2 条更新），4 枚 Critical。排第一的不是任何 ABAP 系统或门户，而是一个 PyPI 包。

四枚严重的分工：

  • CVE-2026-89111（10.0） — SAP Cloud SDK for Python 0.45.2 之前。多租户 BTP 应用里，SDK 会把配置好的令牌 URL 第一个 DNS 标签替换成租户子域；修复前不校验，于是任何能影响 tenant_subdomain 的输入（请求 Host、请求头、JWT claim、URL 参数）都能把带着 client credentials 的令牌请求指到攻击者服务器。CWE-918
  • CVE-2026-89110（9.9） — NetWeaver Visual Composer，VC70RUNTIME 7.50。权限校验不足（CWE-749），低权限用户可对预配置远程系统调用内部操作，Scope Changed，后果取决于那条远程连接有多高权限。这正是 2025 年 CVE-2025-31324（10.0 未认证上传，数日内被在野利用）的攻击入口组件
  • CVE-2026-89107（9.9） — S/4HANA 的 Manage Substitution/Validation Rules，S4CORE 105–109。规则定义里的领域脚本被当 ABAP 代码解释执行（CWE-94），有对应业务权限的已认证用户可完全接管系统
  • CVE-2026-89108（9.1） — Manufacturing Integration and Intelligence，XMII 15.4 / 15.5。配置服务缺授权校验（CWE-862），MII 管理员能在底层 Java 应用服务器上造出高权限账号

时间差才是这条的重点：PyPI 上 0.45.2 早在 8-21 就已上传，公告到 10-13 才发。习惯随手升级依赖的团队早就修好了却不知道；把版本 pin 在旧版、等公告再动的团队，这一个多月完全裸奔，扫描器一句话都不会报。修复本身很朴素：按要求用 RFC 1123 DNS 标签规则校验子域。

另有 CVE-2026-89113（Commerce Cloud SQL 注入，8.8）与 CVE-2026-58249（NetWeaver / Web Dispatcher 的 ICM 内存破坏，7.5），后者未认证请求即可打崩进程，影响 7.53、7.54、7.77、7.93、9.16 等多个内核版本——面向公网的 Web Dispatcher 应该排在高危项之前处理。目前无来源报告这些漏洞已被利用，也都不在 KEV。

Mage OSS 未认证会话伪造 9.8 — 报错了，但会话已经建好；而"最新版"其实没修

CVE-2026-111823 · GHSA-93gm-r5p2-wxq7 0.9.80 仍不安全

数据管道编排工具 Mage OSS 存在严重认证绕过。机制简单到有点荒谬：OAuth 回调逻辑（mage_ai/api/resources/OauthSessionResource.py）在请求携带无法识别或空的 provider 名时，异常处理捕获了解析错误、写了日志，却没有终止流程——执行继续落入默认的会话令牌创建逻辑，请求里带的邮箱被用来查找甚至创建账号。身份根本没经过任何有效 OAuth 提供方验证，攻击者却拿到了有效会话。CWE-390（检测到错误状态却不采取动作）。

5 高危

一次上游泄露，被切成 38 份勒索单 — n0n 向 18 国海运企业索要 12.2 亿美元

2026-10-12 上架 · 10-19 13:27 UTC 截止 38 家 / 18 国

勒索团伙 n0n 于 10-12 在暗网泄漏站一次性挂出 38 家海运相关组织，横跨 18 个国家——航运公司、码头运营商、物流企业、船舶管理公司。索要总额约 12.2 亿美元，单家 240 万至 1400 万美元（比特币），截止时间就在今天 13:27 UTC。

关键判断：这可能不是 38 次入侵。安全公司 Cydome 指出，38 家里至少 21 家是韩国海运软件与 IT 服务商 CyberLogitec 的已记录客户，初步分析认为 n0n 很可能把源自 CyberLogitec 的一次泄露按客户切片，做成了 38 份单独的勒索单。SOCRadar 的方向一致：多家受害者的数据集都很小、且高度集中于特定应用，更像共享同一个应用或同一个漏洞，而不是 38 次独立攻击。泄露内容据称含凭据、个人信息与 EDI 报文，部分数据已有数年历史——相关账号与对接配置可能早该轮换。

必须加的限定：被挂上泄漏站不等于该公司自己的系统被入侵。这几家截至 10-15 均未确认遭入侵。

值得关注的原因：

  • 纯数据勒索比加密勒索更难防。n0n 2026 年 9 月才出现，不加密、没有解密钥匙、没有"付钱恢复系统"这条路，只有"付钱别公布"。备份做得再好也挡不住
  • 信任一次上游，代价按客户名单倍增。海运业的 EDI、订舱、单证系统天然互联，一家软件商同时是几十家船公司与码头的接口方。攻击者成本是一次，收益是 38 份
  • 截止时间就是今天。13:27 UTC 之后是否真的公布，是观察这个团伙"说到做到"比例的样本

当日勒索面快照：截至 10-19 01:50 UTC 的 24 小时内 23 家组织被 8 个团伙挂出（n0n 10 家、Qilin 6 家、Cloak 2 家）；前一日 23 家，7 日均值 46.0 家；10 月至今 645 家，2026 年累计 8,672 家。单日波动大，看趋势别看一天。

6. FortiSIEM 路径穿越（CVE-2026-106173，9.4）：厂商公告和 CVE 记录的受影响版本对不上

10-13 随 Fortinet 月度 PSIRT 发布，公告 FG-IR-26-180：gRPC 服务 phQueryMaster 存在任意文件写入，未认证攻击者可用特制报文执行任意代码或命令。问题在于公告只说 7.5.0 受影响，Fortinet 作为 CNA 提交的 CVE 记录却列了 7.5.0、7.4.0–7.4.2、7.3.0–7.3.5、7.2.0–7.2.7、7.1.0–7.1.9、7.0.0–7.0.4，且 7.0–7.4 各线都没给修复版本。公开信息无法判断哪个对。能确认的只有三条：7.6 不受影响；7.5.0 升到 7.5.1；封住 TCP 27918 能阻断该问题。CVSS 时间分项里利用代码成熟度为 High。SIEM 为了收日志通常对内网开很大的入站规则，这个 workaround 恰好要求把规则收紧——先做这件事。

7. Metasploit 收录两枚本地提权：任何本地 shell 都能一键变 root

Rapid7 在 10-09 的 Metasploit 周报加入两个模块：linux/local/dirtyclone_cve_2026_43503（PR #21613）与 linux/local/cve_2026_3888（PR #21532）。DirtyClone（CVE-2026-43503） 是 Linux 内核缺陷，DirtyFrag 家族第四个成员；JFrog 的 Eddy Tsalolikhin 与 Or Peles 于 5-19 独立发现并报告，5-21 合入主线、5-23 发 CVE，首个修复 tag 为 v7.1-rc5，JFrog 6-25 发分析时保持 PoC 私有、当时无在野利用。CVE-2026-3888 是 Ubuntu snapd 竞态：snap-confine 建沙箱依赖 /tmp/.snap，而 systemd-tmpfiles 会周期性清理这个目录；时间点可预测时攻击者能抢先重建目录并放入载荷，下一次沙箱初始化时 bind mount 就把文件暴露到 root 上下文，清理周期带来 10–30 天窗口。实际意义很直接：Web shell、被偷的低权限登录、被攻陷的容器用户，这些"半只脚"如今有现成的 shell→root 路径。打了补丁没重启内核的机器仍然中招。

8. Gitea 28.2.0 批量披露：OpenID 2.0 的无请求断言可以绑到你头上

CVE-2026-104627：安全设置里的 OpenID 关联回调接受未经验证的 OpenID 2.0 正向断言，不检查当前登录用户是否发起过这次关联。因为 OpenID 2.0 允许"未被请求的断言"，攻击者控制的提供方可以把攻击者身份绑到受害者账号，之后通过 OpenID 登录以受害者身份进入，且这条路径不经过本地 TOTP 或 WebAuthn 校验；修复后要求带时效、绑定用户的 state 值。CVE-2026-97859：/api/v1/users/{username} 下 7 条路由（followers、following、starred、subscriptions、keys、gpg_keys 等）漏挂 individualPermsChecker，已认证用户可读受限或私有可见性用户的关注/粉丝、星标仓库、公开 SSH 与 GPG 公钥，修复于 1.27.3 与 28.0.0。CVE-2026-110324：档案可见性校验只加在 GET，POST /{username}（关注/取关）只校验登录，可拿到私有档案用户的全名、所在地、网站与简介，修复于 28.1.0。三条合起来是一个熟悉的形状：双因素认证做得很认真，绕过去的那条旁路没人看。

9. 英国 NCSC 更新 TLS 指南，正式纳入后量子配置

10-15 发布，跟进 IETF 的 RFC 10024（TLS 1.3 的后量子与传统混合密钥协商）。要点：TLS 1.3 是唯一会支持后量子的版本，TLS 1.2 及更早不会被升级补齐，还在跑旧版本的应立即迁移；混合式与纯后量子两类密码套件都推荐；时间表沿用既有口径——2028 年完成目标定义、发现与初步计划，2031 年前完成最高优先级迁移，2035 年完成全部。NCSC 表示待相关 RFC 定稿后还会更新 IPsec 指南并补充 TLS 后量子认证建议。对普通团队最实际的落地动作只有一条：先做密码学资产清单，尤其是需要保密十年以上的数据通道。

10. 澳大利亚 ACSC 就海外制冷系统攻击发布 OT / 边缘设备告警

澳大利亚信号局的 ACSC 针对运行联网运营技术（OT）（含商用制冷系统）的组织发告警，背景是海外发生的同类攻击（10-14 法国数百家超市冷库被远程加热事件）。ACSC 表示尚未观察到澳大利亚基础设施被主动针对，但建议立即评估暴露面：把 OT 接口与边缘设备从公网直接暴露中撤出、启用强认证与网络分段、及时打补丁、监控异常自动化动作。这条尤其适用于托管服务商、设施运营商，以及那些从承包商手里继承了远程访问通道、却没有完整资产清单的组织。

11. 今天到期的两个 KEV：都带"取证排查"标记

CISA 于 10-16 把两条边缘设备漏洞加入 KEV，联邦修复期限均为 2026-10-19，且都标注 forensic triage——不是打完补丁就算完，还得查有没有已经被打。CVE-2026-102764（BeyondTrust Remote Support，认证绕过/欺骗）被 Mandiant 关联到威胁集群的零日利用；CVE-2025-61624（FortiOS / FortiPAM / FortiProxy / FortiSwitchManager，CLI 路径穿越，读写权限管理员可写删任意文件）被 Unit 42 关联到 FortiGate 植入体。对非联邦机构而言这个日期没有强制力，但含义明确：利用代码已经在流通，而这两类资产都在边界上。
