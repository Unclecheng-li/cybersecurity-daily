今天最好的几个洞，没有一个是今天写错的

十年前嵌进页面的第三方统计标签，服务商倒闭、域名过期，被攻击者买走之后，所有还引用那段脚本的网站就在替别人投毒——这是一条零点击的 iPhone 漏洞链，入口在 DNS 的续费记录上，站主什么都不用改。同样在今天：PHP 那两枚 9.2 的补丁发了三天，攻击者已经拿它拉起 Mirai 变种扫了数百万次；Aruba 的无线控制器一次掉出 72 个洞、8 枚满分，而那个协议从没在威胁模型里出现过；Pillow 出问题的地方不是图片，是文件名。漏洞是新的，但被利用的地基全是旧的——安全债的到期日，通常比披露日更早。

DeadTag 与 DarkSword：十年前的统计标签，成了零点击投毒的入口

2026-10-23 披露 · 10-24 慢雾统计出 1500 个相关钓鱼站 660 个过期域名 · 每月 1.35 亿次访问暴露 · 无 CVE 无补丁

安全研究者 Scott Helme（Report URI）与移动安全公司 iVerify 披露了一个被命名为 DeadTag 的长期活动，机制简单到近乎荒谬：大量网站在十几年前嵌入了第三方服务的标签——分析、广告、客服小挂件。提供方后来倒闭或放弃续费，那段外链脚本却还留在页面里。攻击者盯着到期域名清单，一旦某个域名释放就立刻买下。买下的那一刻起，所有还引用旧标签的网站、每一个页面、每一个访客，都开始在不知情的情况下加载攻击者的代码——站主什么都没改，也什么都没察觉。

规模是这么量出来的。研究者确认 660 个以上过期并被重新注册的域名仍在数千个网站里活着，估算每月约 1.35 亿次访问暴露在这条链上。它不需要黑进任何网站，因为它拿到的是别人早就忘了的、还在自动执行的那段代码。

环节实际发生的事
沉积网站十年前嵌入第三方标签（统计、广告、客服），提供方倒闭后域名不续费
接管攻击者按清单监控域名释放，逐一买下；买下即继承所有引用者的流量
筛选脚本先判断访客值不值得打：普通人引向诈骗与广告，iPhone 送进专业漏洞套件
落地Coruna 打较老版本 iOS；DarkSword 的 P7 变体打特定较新版本

两套套件都打浏览器本身，不是钓鱼页、不是假 App。也就是说不需要点击、不需要下载、不需要授权，页面打开就已经站在中招路径上了。拿下之后直取 Keychain 里的账号密码、加密货币钱包本地私钥、备忘录、通讯录与位置，动机指向资金。

投递渠道被确认的有两条，都很"日常"。

渠道细节
恶意 Instagram 广告iVerify 发现一条世界杯主题广告，某客户组织的员工在刷 App 内信息流时被自动触发感染
受感染的电商站数百家 PrestaShop 网店上找到 DarkSword 加载器，藏在伪装成分析代码的目录里；另有一家零售商同时加载 Coruna 与 DarkSword

国内方向的补充来自慢雾。10-24 凌晨，余弦表示旗下 MistEye 系统全网狩猎发现已部署超过 1500 个与 DarkSword 相关的钓鱼站点，覆盖电商、仿冒币安、仿冒 OKX、虚假加密钱包、游戏与兑换场景；10-24 上午他又提醒尽快更新 iPhone 与 iPad，并特别说明要警惕已安装的部分 App 被投毒——不是"别点链接"，而是设备上已经装好的应用本身可能带毒。

值得关注的原因：第一，这条链的入口既不在受害者身上，也不在网站代码里，而在 DNS 的续费记录上——它绕开了所有常规防守动作，你不用钓鱼、不用投毒、不用找 0day 入口，你只需要等。第二，它把零点击从定向打击变成批量投喂：过去的 iOS 零点击打的是记者和部长，现在一条广告、一个还挂着旧标签的页面，就能按机型把目标筛出来。第三，这是一次对"资产清单"定义的挑战——你的资产不只是你拥有的域名和服务器，还包括你页面上还挂着哪些早就不用他家服务的标签。可执行的动作很具体：抓一遍全站外链脚本域名，去掉一切已失效或不再维护的；对没有续费保障的第三方依赖做本地化；给不可信脚本加 CSP；手机端把 iOS 更新提到跟改密码同等的优先级。归属方面，多方分析尚未形成一致结论，本文只记技术链路与基础设施事实。

PHP2Shell 三连：武器化几十小时，但地下论坛说公开 PoC 大多是"AI 垃圾"

前情 193 与 194 与 195 期 · 今日三块新增事实 CVE-2026-109618 与 109619 各 9.2 · 第三风险面 115560 官方不发紧急补丁

这条是本系列连续第四天跟踪，今天有三块新增事实，其中第三块最值得读，因为它和恐慌情绪相反。

新增一：从"被尝试"变成"被规模化尝试，并开始传播僵尸网络"。10-23，Sophos 与 Arctic Wolf 披露，攻击者正用这两枚漏洞把受害主机拉进一个新增强的 Mirai 变种，Sophos 命名为 Potassium，其命令控制使用硬编码的加密地址。规模：全球数百万次注入尝试；Cloudflare 侧在披露后 45 分钟就见到数万次，到 10-22 早间升至数百万次；Amazon 蜜罐记录的首次尝试仍是 10-17，比补丁早四天。

新增二：官方又指了一个风险面，但没有紧急补丁。10-23 PHP 官方发布信息级公告，指出第三个风险面，临时编号 CVE-2026-115560：应用在进程内用 ini_set() 把 session.serialize_handler 从 php_binary 或 php_serialize 运行时切成 php，且切换发生在 session_start() 之前、且会话上传进度开着时，存在代码执行风险。官方评估现实风险低、不发紧急补丁，缓解只有一行：session.upload_progress.enabled=0——和 10-21 修 109619 时给的那条一模一样。目前无在野。

新增三：地下论坛的《PoC 鉴定报告》。Flare 跟踪了 Exploit.in、XSS、Dread、BreachForums 等八个论坛在披露后 48 小时内的讨论，结论是公开的 PoC 把 PHP 打崩远比弹 shell 靠谱。

ArubaOS 一次修 72 个漏洞、8 枚 10.0：58 个不用登录，22 个打在管理协议上

2026-10-22 公告 HPESBNW05162 · 10-23 集中报道 72 个 CVE · 8 枚 CVSS 3.1 10.0 · 无公开利用 无在野 未入 KEV

HPE 于 10-22 发布安全公告 HPESBNW05162（revision 1，严重级别 Critical），修复运行在 AOS-8 与 AOS-10 上的 72 个漏洞，涉及 Mobility Conductor、Mobility Controller、Central 托管的 Mobility Gateway、AOS-10 AP 与 AOS-8 Instant AP。其中 8 枚 CVSS 3.1 评为满分 10.0。

为什么 PAPI 那 22 个特别刺眼。PAPI 是 Aruba 用来管 AP 的私有协议，监听 UDP 8211，是无线基础设施"自己跟自己说话"的通道。同一批里还有一枚独立的 CVE-2026-79855——SSH 守护进程的认证绕过，它和 PAPI 那些一样，都是"不用有效凭据就能摸到管理面"的路。管理 Web 界面在 HTTPS 4343。另有两个管理员级漏洞能让设备崩到必须人工现场重启——对 AP 分散在几十栋楼的校园或医院来说，这就把一个软件缺陷变成了跑腿任务。

值得关注的原因：第一，这 8 个 10.0 不是 0day，是技术债到期——PAPI 这种私有协议常年只在设备之间用、不在公网上"看起来"暴露，既少有外部研究也少有内部重写，一次集中审计就掉出 22 个洞。第二，58 比 72 这个比例比任何单点分数都更能定义风险：只要管理接口能被摸到，账就不用输密码。第三，无线控制器是身份与流量的十字路口，拿下它就能看流量、改分流、动 VLAN、改认证，而且固件级访问能活过重装系统。动作建议：先封锁所有边界的 UDP 8211 与 4343，把管理接口塞进专用 L2 段；按设备实际分支逐一匹配五个修复版本（AOS-8 与 AOS-10 混跑最容易漏）；给管理面登录失败与 PAPI 异常加告警。

M365 被"令牌喷洒"打穿 79 家组织：改密码在这里是无效动作

Huntress 2026-10-22 公布 · 观察窗 07-14 至 09-22 497 次成功 · 20 万次失败 · 48 台影子设备 · 19 家 3 小时内换 MFA

Huntress 公布了一次长达十周的 BEC 行动，覆盖其客户中的 79 家组织。核心数字如下。

指标数值
成功登录497 次
失败尝试超过 20 万次
影子设备至少 48 台
MFA 被换掉的组织19 家，均在首次可疑登录后 3 小时内
回放地址193.26.115.0/24 内六个 IP，分四个阶段，阶段间隔一到两周
基础设施德国汉堡托管商 1337 Services GmbH，Entra ID Protection 独立标记过其中几个地址

令牌从哪来。三条路，全都发生在"正常登录"里：AiTM 中继（假登录页把真实微软登录页与 MFA 提示透传给受害者，登录完成后签发的会话令牌被截走）、设备码钓鱼（骗受害者在微软官方页面输入攻击者给的码）、以及正常登录过程中的社会工程。关键在于令牌是在 MFA 之后签发的，所以拿着它的人不必再过一次 MFA。

"喷洒"这个词的由来。攻击者把偷到的一批令牌批量回放到很多租户上——和密码喷洒同一个套路，只是把"猜密码"换成"用偷来的令牌"。速度极快：7-21 一案里，受害者在 MFA 提示后 12 分钟就看到会话从那个托管商地址出现；9-22 一案是 4 分钟。

进去之后，重点全在"续命"。

  • 48 台影子设备注册进受害者 Entra 目录，命名规律统一：DESKTOP- 加八位十六进制。注册过的设备会一直留在目录里，直到有人手动删。
  • 19 家组织里，受害者原有 MFA 方法被清空、换成攻击者自己的。7-21 那一例不到一小时就给账号挂上了一个名为 "iPhone 13" 的验证器 App。挂上之后攻击者可以随时自己过 MFA，而且这把钥匙在改密码之后依然有效。
  • 收件箱规则名字起得像噪音：.、sss、iT——把特定来信删掉，或标记已读后丢进 RSS 订阅与对话历史这类没人看的文件夹。有一例更精细：先用被控邮箱给外部会计发工资相关邮件，然后改规则抓所有含 payroll、direct deposit、bank、bonus 的邮件，五分钟后再建第二条，把那位会计的全部来信隐藏起来。

9-11 起换了打法：切到新地址并跑了一个自动化程序重用抓到的令牌，四天内在近 30 家组织完成数百次成功登录。同一天这个地址被拦下 1052 次——1052 次全部来自四家配置了条件访问策略的组织。

值得关注的原因：第一，"改密码"在这里是无效动作——密码重置不吊销已有会话、不删影子设备、不移除攻击者注册的验证器、也不清收件箱规则，而这四样才是真正的落脚点。第二，条件访问策略在数据上被证明有效：1052 次拦截全部来自那四家，同一批令牌在其他租户上照样进得去。第三，影子设备的命名规律是极好的检测抓手：DESKTOP- 后接随机十六进制，正常企业命名规范里几乎不会出现。动作：搜 Entra 里所有该形态设备；比对 MFA 方法注册时间与登录时间；审名字异常（点号、sss、单字母）的收件箱规则；有条件访问的，把"全部用户 + 全部云应用 + 全部客户端类型"无条件覆盖。

Pillow CVE-2026-112900（9.2）：出问题的不是图片，是文件名

13.0.0 于 2026-10-16 修复 · GitHub 公告 10-21 定为 9.2 影响 2.6.0 至 12.3.0 · 月下载约 4.36 亿次 · GitHub 评 9.2 官方列 Medium

Pillow 的 EPS 处理会把调用方给的文件名直接交给 Ghostscript，自己不做检查。Ghostscript 会把以短横线开头的"文件名"当成命令行选项读，而以 @ 开头的名字可以指向另一个文本文件，让那个文件里的内容变成追加参数。于是：一个完全无害的 EPS 文件，配一个攻击者能控制的文件名，就能让宿主机执行任意操作系统命令。

Quest Diagnostics 检验下单入口被打开：三分之一的美国成年人走这条路

2026-10-21 发现并向 SEC 提交 8-K · 10-23 官网更新进展 Quanum LSM 被未授权访问 · 患者数据已确认被访问 · 暂无团伙认领

美国临床检验巨头 Quest Diagnostics 在 10-21 发现未授权访问，当日向 SEC 提交 8-K 并在官网挂出说明页，10-23 上午更新进展。被打开的入口是 Quanum Lab Services Manager（LSM）——医生、医院员工、诊所行政用来下单、查结果、追进度、订耗材的门户。

7. Oracle 紧急警报 CVE-2026-91403（9.1）：eMudhra 那八把弱私钥，Java 终于不认了

10-21 Oracle 发布季度外安全警报，CVE-2026-91403，CVSS 3.1 9.1，位于 JSSE（Java 的 TLS 实现）组件。不需要认证、不需要用户交互、复杂度低；只影响机密性与完整性，不影可用性。根因按 OpenJDK 公告是八张被攻陷的中间 CA 证书——即本系列 10-21 期报过的 eMudhra 那批弱 P-384 私钥：攻击者能用它们给任意主机名签发证书，Java 客户端照单全收，中间人就位后 HTTPS 的身份校验形同虚设。受影响：Java SE 8u511、8u511-perf、11.0.33、17.0.21、21.0.13、25.0.5、27.0.1，GraalVM for JDK 17.0.21 与 21.0.13，GraalVM EE 21.3.20；OpenJDK 8 至 27 全系列为受影响。最关键的一句：这枚不在 10-20 的季度 CPU 里，打过十月 CPU 的仍然中招。缓解可替换 blocked.certs（Java 8 叫 blacklisted.certs）保留自定义条目，或开 -Dcom.sun.net.ssl.checkRevocation=true 与 -Dcom.sun.security.enableCRLDP=true，JDK 17 以上还可用 jarsigner -verify -revcheck -strict。这条把 10-21 期那句"吊销数据到不了非浏览器客户端"补上了后半句：现在它到了，只是比浏览器晚了六天，而且要再走一次计划外的紧急发版。

8. 申万宏源（香港）：收到疑似勒索讯息，主动通报香港警务处

10-23，申万宏源（香港）有限公司依据港交所上市规则 13.09(2)(a) 与《证券及期货条例》XIVA 部内幕消息条文刊发公告：集团近期收到疑似勒索讯息，对方声称获取了集团部分资料并索要回应。公司已即时启动资讯科技网络安全应变及处理机制、开展多维度安全加固，并主动向香港警务处通报、保持密切沟通。截至公告日，交易、结算等核心业务及管理系统运转正常，各项业务正常开展，未涉及任何客户资产或资金损失；若后续核查确认产生重大影响将另行公告。值得记的是措辞——"声称获取"。窃密加曝光威胁已是勒索产业的主流形态，而金融机构最难的从来不是防守，是"数据到底有没有丢、丢了多少"这个核查窗口：窗口越长越被动。这套动作（先启动机制、再报警、同时发公告、核心业务不停）本身就是一个可抄的模板。

9. Symantec：node.exe 被当成 LOLBIN，以太坊智能合约当 C2

自 2026 年 2 月起，多拨攻击者开始滥用正版签名的 node.exe：不放恶意 exe，而是装官方 Node.js 运行时去跑恶意 JavaScript，把逻辑藏在解释型脚本里，AV 与 EDR 的启发式几乎不响；持久化靠写进 Windows Run 键。受害面覆盖政府部门、科技公司、酒店，亚洲与美国都有。代表案例是亚洲某科技公司：投 AdaptixC2 与 Cobalt Strike Beacon 反复被拦，干脆从 nodejs.org 下官方安装包，用运行时跑一个走以太坊区块链网关的植入，即 EtherHiding，指令藏在智能合约里。同一团伙还打过一家美国 fintech，用的是 Rust 后门 C2Looper（Zscaler 此前记录过，疑似为勒索团伙铺路），两起共享 C2 域名 datalayerservice。另有 ModeloRAT 与初始访问中介 Woodgnat 与 KongTuke 同行，该中介被指与 Qilin、Interlock、Rhysida、Akira、8Base、Black Basta、Embargo 多个家族有关；也观察到 AsukaStealer 的 Node.js 版（打亚洲酒店）与 EtherRAT。检测抓手很具体：非开发机上出现 node 安装、Run 键里出现调 node.exe 的项、非开发主机向以太坊公共 RPC 端点的流量。

10. sol-live：假 Solidity 面试仓库，后门藏在 .vscode/settings.json

10-23 慢雾披露一个名为 sol-live 的 GitHub 仓库，伪装成 Solidity 面试练习项目，瞄准 Web3 开发者——套路是"我们有个编码测评，你 clone 下来用 VS Code 打开"。载荷在 .vscode/settings.json：里面是一条下载并执行的终端命令，跟智能合约练习毫无关系。两处遮挡很讲究：命令前塞了几百个空格，用编辑器打开时被推出视野；同时用文件排除规则把 .vscode 目录从项目树隐藏，肉眼翻目录根本看不到。触发条件：macOS 与 Linux 上需要用户在工作区里主动开一个终端；Windows 链路未确认（慢雾归因于引号处理问题）。载荷三块：收集浏览器登录数据库与钱包扩展存储、拷贝 macOS Keychain、扫描并上传本地文件；远程命令执行并给交互 shell；监控剪贴板（换钱包地址类攻击的前置）。慢雾还找到另外 8 个用同类"终端下载执行"手法的 GitHub 项目，名字未公布。没有 CVE、没有 CVSS、没有 IOC。这条与 10-24 的 iOS 提醒、以及本期头条的 DarkSword 是同一个资金流向：加密资产相关的开发者与用户，正在被当成一条独立产品线来经营。

11. x402 SDK：agent 自己签名的付款，一次恶意 API 就能把余额掏空

x402 系列 SDK 存在一个严重缺陷：默认客户端不设单笔交易的消费上限，直到 8-18 才发布补丁。后果很直接——只要 AI agent 被配置为"自动签名付款、不经人工审批"，一个恶意 API 就能把它的全部代币余额一次性划走。有消费上限或有人工审批环节的配置不受影响。这条的价值不在漏洞本身，在默认值：agent 能自己花钱这件事，额度限制应该像信用卡默认限额一样是开箱必备，而不是一个可选开关。往期报过的 Phantom 与 CARLIY0S 说明攻击侧已经把多模型编排用起来了，防守侧"给 agent 一张有额度的卡"却还没成为默认。

12. 两枚小洞：filelock 的锁能被"骗过期"，Perl 的 12 字节 Accept-Language 能烧 CPU

filelock CVE-2026-112906（CVSS 4.7，10-23 发布）：4.1.0 至 4.2.0 判定"陈旧锁"的依据是 (inode 号, 修改时间) 这个二元组。在 inode 会被快速复用的 Linux 文件系统上，本地攻击者可操纵这两个属性，让正在等待的进程误把活锁当成死锁删掉，两个进程同时进临界区。修复 4.2.1（commit 740ff66）加了 ctime、做 inode pinning、并强制原子化换名。CWE-694。

HTTP::Headers::ActionPack CVE-2026-113877（CPANSec，10-24 发布）：0.10 之前的版本把 Accept-Language 里每个 range 不转义地插进正则 /^$range\-/i，头里的正则语法直接进了引擎。一个 12 字节的 range 如 (a?|b?){26}z 就能回溯数秒，量词每加一档时间翻倍；非法 range 比如 ( 直接编译失败，让 choose_language 抛死。CWE-624。

为什么放一起：都是"看起来无害的辅助功能"——一个是文件锁，一个是语言协商。它们不在任何人的威胁模型里，却都在关键路径上，修起来都只有几行。攻击面清单里最该补的一栏，往往是这些"没人认为它是安全组件"的组件。
