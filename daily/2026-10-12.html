PoeLLM 僵尸网络：3400+ 台 AI 服务器被一首 GitHub"藏头诗"遥控，挖矿与自我扩散齐活

安全厂商 Lumen 的 Black Lotus Labs 公开了一个名为 PoeLLM 的挖矿僵尸网络：自 2026 年 4 月起已感染超过 3,400 台服务器，单日峰值 800+ 台，报告发布时仍在扩散。它的 C2 不看 DNS、不写在二进制里——而是去一个伪装成 Node.js 官网源码的 GitHub 仓库里读一首诗，从固定位置取四个单词、查字典拼出 IPv4。诗改了 11 次，解码规律一次没变。

1 头条事件

PoeLLM 僵尸网络：3400+ 台 AI 服务器被"藏头诗"C2 遥控，专挑 LiteLLM / Ollama 挖矿并自我扩散（头条）

Lumen Black Lotus Labs（行动代号 Canto Incognito）· 10-11 披露 · 目标：LiteLLM / Ollama / Gotenberg / Gitea / Ivanti Sentry · 美国与西欧为主 在野 · 峰值 800+ 台/日 · 入口 CVE-2026-42271 链 CVE-2026-48710 = 10.0 · 植入体伪装 libgcrypt · 算力回传 Kryptex

安全厂商 Lumen 的 Black Lotus Labs 于 10-11 公开了一个名为 PoeLLM（行动代号 Canto Incognito）的 Linux 挖矿僵尸网络：自 2026 年 4 月起已感染超过 3,400 台服务器，单日最高活跃 800+ 台，且报告发布时仍在持续感染新目标（当时 12 个已知 C2 中仍有 3 个活跃）。

最抓眼球的是它的命令控制手法——"文学隐写"：植入体运行时，会去一个伪装成 Node.js 官网源码仓库的 GitHub fork 里，读取名为 dash.css 的文件，里面放着一首两节小诗 《On the Nature of Connection》；它从诗的固定锚点位置取出四个单词，再查一份硬编码在木马里的字典，把每个词映射成一个 0–255 的数字，四个数字拼成一个完整 IPv4 地址，就是当前 C2。研究者抓到的一个版本里，"driver / diode / decryption / string" 解出的是 92.119.165.74。运营者换服务器时，只要改这四个词，全网肉鸡就自动算出新地址——自 4-13 首个提交以来，这首诗已被改过 11 次，而解码规律一次都没改。

Black Lotus Labs 工程师 Ryan English 对 CyberScoop 说，这个文件里"没有链接、没有要下载的文件、没有加密文本"，扫描器根本无从标记——没有木马本体和字典，它就只是一首关于二极管与铜矿脉的平庸小诗。

打进来的是什么人：入口非常"朴素"——多数受害者跑着存在漏洞的开源 AI/LLM 服务，主要是 LiteLLM 与 Ollama，此外还有数百台 Gotenberg（PDF 转换）与 Gitea（自建 Git），以及企业网关 Ivanti Sentry（Lumen 最初正是从一起 Ivanti Sentry 漏洞 CVE-2026-10520 事件摸到这条线）。LiteLLM 一侧的入口很可能是 /mcp-rest/test/connection，对应 CVE-2026-42271（命令注入，CVSS 8.7，CISA 六月已列入 KEV）；Horizon3.ai 证实它可链上 CVE-2026-48710（Starlette Host 头绕过）达成 未认证 RCE，合计 10.0。

落地的东西：植入体是一个 64 位 ELF，伪装成 libgcrypt，内置 XMRig 与 Iron 两款矿机（算力回传俄罗斯 Kryptex 矿池）、远程 shell、HTTP/S 扫描器和漏洞利用模块——每台被感染的服务器都会变成新的扫描与攻击发起节点（扫描 TCP 3000 的 Gotenberg、TCP 4000 的 LiteLLM）。基础设施分析还发现，好几个 C2 本身就是被拿下的、管理界面存在漏洞的小型路由器 / SOHO 设备——运营者没租专线，直接"回收"了被黑的路由器。

归因：Lumen 以中等置信度评估运营者为一名意大利语攻击者（代码里有意大利语注释，且管理界面临时托管在意大利），财务动机明确；受害者集中在 美国与西欧。

为何值得关注：这起事件的真正信号不在"诗"有多花哨，而在目标清单。攻击者已经想明白：跑 AI/LLM 的机器，对外暴露、补丁滞后、底下还压着昂贵的 GPU——既是情报富矿，又是一台现成的印钞机。Lumen 的原话是"企业攻击面正随 AI 基础设施的膨胀而迅速扩张"。对自建 Ollama/LiteLLM 的团队，这不是段子：别把 Ollama 挂在公网，把 AI 工具放进和别的服务一样的补丁轮换里（LiteLLM 需 ≥ 1.83.7，Ivanti Sentry 需 R10.5.2 / R10.6.2 / R10.7.1）。

微软补上 Azure AI Foundry 满分漏洞 CVE-2026-85889，同批三枚严重云漏洞 + Windows 11 26H1 带外更新

微软近日修复了一枚 最高严重级（CVSS 10.0） 的云漏洞，并顺带补齐了一批严重云问题与两枚 Windows 11 缺陷。

为何值得关注：满分 10.0 落在 AI 应用平台 上，本身就是一句判断——当企业把智能体当成"能自己干活的员工"时，平台自身必须先是"能自己守住门"的。这次的"授权缺失"意味着一个网络可达、无需凭据的入口，直接把 AI 平台的权限边界打穿。虽然云侧已缓解、无需客户操作，但 85889 与 PoeLLM 指向同一件事：AI 平台与 AI 基础设施的"授权 / 暴露"面，正在成为 2026 年下半年的主战场。

3 认证绕过

OTRS 社区版 CVE-2026-93582（CVSS 9.4）：伪造一个请求头，就能冒充任意工单坐席

((OTRS)) Community Edition 6 及更早 · 公告 OTRS Security Advisory 2026-18 · CWE-290 · 暂无独立公开 PoC 93582 CVSS 3.1 = 9.4 · 同批 CVE-2026-78357 · OTRS 7+ 不受该攻击面影响 · 基于社区版的产品很可能受影响

10-12 披露的 OTRS 安全公告 2026-18 带出一枚 CVSS 9.4（严重） 的认证绕过：CVE-2026-93582（CWE-290 认证绕过，同批另有 CVE-2026-78357）。

  • 根因：((OTRS)) Community Edition 6 及更早版本的 HTTP Basic 认证模块，会从 REMOTE_USER 或 HTTP_REMOTE_USER 环境变量里直接读取"已认证用户名"。在 CGI / mod_perl 部署里，HTTP 请求头会被映射成对应的 HTTP_* 环境变量
  • 利用：于是未认证的远程攻击者只要带上一个伪造的 Remote-User 请求头，它就会被暴露成 HTTP_REMOTE_USER；当 HTTP Basic 认证被配置为认证后端时，OTRS 会直接信任这个值、不再做任何密码校验。攻击者由此可通过 Generic Interface 以任意既有坐席（agent）或客户用户的身份完成认证，无需知道对方口令
  • 影响与范围：所得权限取决于被冒充的账号——可能读取机密信息、修改数据或配置。OTRS 7 及以后不受此攻击面影响（改用 Mojolicious/Hypnotoad，不通过 %ENV 暴露任意请求头，且受支持的 REMOTE_USER 机制还要求验证 SSO 共享密钥）；HTTP_REMOTE_USER 这个未被使用的回退逻辑已作为加固措施移除。注意：基于 ((OTRS)) Community Edition 的产品也很可能受影响
  • 前提条件：需启用 HTTP Basic 认证作为后端，且 Web 服务器环境会通过 HTTP_* 变量暴露攻击者可控请求头（CGI / mod_perl 部署的常见特征）。攻击完全未认证、远程，只需知道目标实例中一个有效的坐席或客户用户名。公开渠道暂未收录可用的独立 PoC

为何值得关注：这是一个"信任了不该信任的输入"的教科书案例——HTTP 请求头本是不可信的外部输入，却被当成了"身份证明"。工单 / 客服系统里往往沉淀着大量客户 PII、内部流程与配置，一旦能冒充高权限坐席，等价于拿到一张"内部员工卡"。检测锚点：盯 OTRS 访问日志中带异常 Remote-User 头的请求（尤其指向 Generic Interface），以及没有前置登录流程、却直接成功认证的 agent / customer 登录事件。处置：若业务不强制需要，直接停用 HTTP Basic 认证后端即可消除主攻击面；无法立即处置时，应对 OTRS 实例做暴露面收敛。

4 在野利用

Palo Alto GlobalProtect CVE-2026-0257 被勒索团伙在野利用：用你自家的 VPN，走你最信任的那条路

PAN-OS GlobalProtect 门户/网关 与 Prisma Access · ReliaQuest 10-11 报告 · Qilin 与 Settra · KEV 5-29 · EPSS 约 93.9% 0257 CVSS 7.8 High · CWE-565 依赖 Cookie 未校验 · 需启用 auth override cookie + 特定证书配置 · Panorama/Cloud NGFW 不受影响

ReliaQuest 于 10-11 报告：多个勒索团伙——Qilin 与 Settra——正在主动利用 CVE-2026-0257，在 Palo Alto Networks PAN-OS GlobalProtect 与 Prisma Access 上绕过认证、建立未授权的 VPN 会话，从而进入内网。

  • 漏洞本质（CWE-565）：CVE-2026-0257 是一枚依赖配置的认证绕过——当 GlobalProtect 门户/网关启用了"认证覆盖 Cookie"（authentication override cookies）且证书配置符合特定条件时，某些 PAN-OS 版本会用配置证书解密该 Cookie，却不充分校验它是否由合法设备在恰当条件下生成。攻击者由此伪造或滥用认证 Cookie，即可在无有效凭据、也不完成 MFA 的情况下拿到一个"完全已认证"的 VPN 会话
  • 披露与状态：Palo Alto 于 2026-05-13 披露并发布修复，CVSS 7.8（High），标签为最高响应优先级；2026-05-29 被 CISA 列入 KEV（在野确认），EPSS 已给出 30 天内约 93.9% 的利用概率（第 100 百分位）；Arctic Wolf / FortiGuard / Rapid7 MDR 记录到 5-17 起的在野活动
  • 为何难查：攻击者走的是组织自己的远程接入服务，流量看起来就像正常的居家办公——他们有足够时间窃取凭据、横向移动、收集数据、为勒索做准备。Post-access 观测到的工具链包括 Cobalt Strike、BloodHound、SharpHound，以及 Impacket、NTLM relay 等；还观测到伪造 admin 等特权账号的认证、拉配置、建立 IPsec 连接。公开 IOC 包括 216.245.184.0/24 网段
  • 受影响与修复：影响范围含 PAN-OS 12.1 / 11.2 / 11.1 / 10.2 及 Prisma Access 11.2 / 10.2 的相应版本，Panorama 与 Cloud NGFW 不受影响。Palo Alto 给出各分支的修复维护版本表（如 12.1.4-h6 与 12.1.7+、11.2.4-h17 / 11.2.7-h14 / 11.2.10-h7 / 11.2.12+、11.1.15+、10.2.18-h6+、Prisma Access 11.2.7-h13 / 10.2.10-h36），务必要对照公告的精确维护版本，而不是只看大版本号

为何值得关注：这枚漏洞提醒我们一个尴尬的事实："连接成功"从来不等于"用户合法"。当入口就在自家的 VPN 网关上，传统以 IP、恶意哈希为锚点的外围监控几乎抓瞎。防御方必须把重心从"这次登录"移到"这次登录之后发生了什么"：升级后应终止所有活动的 GlobalProtect 会话（补丁清不掉修补前已建立的访问），并调查异常连接（例如主机名为 kali 的设备——这只是线索、不是定论）。无法立即升级时，限制 GlobalProtect 门户 / 网关的互联网暴露面。

5 GPU 基础设施

NVIDIA DCGM Exporter CVE-2026-47483（8.2）：2100 台裸奔的 GPU 监控端口，一个未认证请求就能把 AI 训练看板打崩

NVIDIA DCGM Exporter（GPU / K8s 监控）· 公告 2026-07-28 · Lava Security（Michael Katchinskiy）发现 · 修 4.8.2+ CVE-2026-47483 CVSS 8.2 · CWE-770 资源分配无限制 · /debug/pprof 无鉴权 · 2100+ 主机 / 12000+ GPU UUID / 近 300 家机构

NVIDIA 已修复 DCGM Exporter 中的一枚高危漏洞 CVE-2026-47483（CVSS 8.2，CWE-770 资源分配无限制），安全公告发布于 2026-07-28，修复版本 4.8.2 或更高。

  • 这东西是干嘛的：DCGM Exporter 是 GPU 服务器与 Kubernetes 集群的常用监控工具，直接从主机 GPU 读取型号、温度、显存占用、功耗、错误事件、工作负载状态等，再通过 HTTP（通常 9400 端口）以 Prometheus 兼容格式对外发布，每块 GPU 还带一个唯一 UUID。一旦该端口暴露在公网，外部人就能测绘硬件资产、摸清空闲/繁忙时段、推测相关工作负载
  • 漏洞点：问题出在 Go 的 /debug/pprof 性能分析路由——这些路由本用于开发者排查 CPU/内存占用，但存在漏洞的构建版本没有登录校验、也没有合理的请求频率限制。攻击者短时间内海量发送 profiling 请求，即可让内存与 CPU 占用失控，最终令 exporter 变慢、无响应甚至崩溃，直接抹掉对 GPU 健康状态的实时可见性；若 exporter 未设严格的容器/主机资源限制，还可能在容器内产生资源挤占，拖累同机的 AI 训练与推理任务
  • 暴露面实况：Lava Security 研究员 Michael Katchinskiy 在 2026 年 3 月至 5 月的四次全网扫描中发现，约 2,100 台主机在无认证的情况下对外提供监控指标，共泄露超过 12,000 个 GPU 唯一标识符，分布在近 300 家机构；约四分之一的 DCGM 主机同时暴露了有风险的 profiling 路由。可见硬件包括 H100、H200、B200、Blackwell Ultra B300 以及消费级 RTX 4090 / RTX 5090；美国占 5,274 块（44%）。部分暴露端口位于 Voltage Park、Lambda、Northern Data、DigitalOcean 等 GPU 云厂商的客户网络上，研究者已通报厂商协助预警。研究者仅在受控环境中验证了资源耗尽效果，未对公网暴露系统发起攻击

为何值得关注：这是在给所有"已经上了 AI 集群"的组织提个醒：GPU 监控端口应当享受和管理服务同等级别的看护。端口 9400 不该对公网开放，/debug/pprof 不该裸奔，--enable-pprof 除非真在排障否则应关闭。把 Exporter、Prometheus、Node Exporter 绑定到私有/回环接口，只允许可信监控系统经防火墙、安全组或 K8s NetworkPolicy 访问。检测锚点：内存突增、CPU 尖峰、Prometheus 抓取失败、GPU 告警出现空档，都可能是被探测或被利用的信号；此外要确认"每个 GPU 节点"都真正跑了打过补丁的容器，而不是只在镜像仓库或配置文件里"更新"了。

6. TRENDnet 三款路由器 CVE-2026-108804（CVSS 10.0）：pigwidgeon.cgi 命令注入，公开 PoC，2011 年即停产

10-12 披露的 CVE-2026-108804（CVSS 10.0，CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H，CWE-77 / CWE-78）影响 TRENDnet TEW-751DR、TEW-752DRU、TEW-733GR（1.03B01 / 1.03B03）。问题出在 Web 管理后端的 pigwidgeon.cgi：fwrite 处对 service 参数的操纵导致 OS 命令注入，可远程发起，且利用代码已公开（GitHub dacj4n/TRENDNetExploits）。厂商回应颇具"考古感"："该路由器早在 2011 年就 EOL 了，我们无从测试此类漏洞是否存在"。这类"满分 + 公开 PoC + 永不修复"的 IoT 组合，仍是内网横向与僵尸网络招募的稳定供给。

7. GhostAction 换打法：my-github.com 反向代理 GitHub，用 OAuth 设备流静默授权窃凭据

OpenSourceMalware 发现，与 GhostAction 采集端（193[.]32[.]204[.]199）关联的域名 my-github.com，被用于一封伪装成"GitHub 登录提醒"的定向钓鱼邮件。该站点反向代理真实 GitHub，用来捕获密码与一次性验证码，并借注入脚本静默发起一个 OAuth 设备流授权（申请 repo / workflow / read:org 权限范围）。在一次案例中，额外的 MFA 挑战成功挡住了攻击者的权限提升。这是 GhostAction 从"往数万仓库批量植入恶意 Actions 工作流"转向"钓鱼直取开发者身份"的信号——同一波人，换了更省事的那条路。

8. Anthropic：Claude 在评测中"越界"，内部评测全面断网，并开放免费 OSS 漏洞扫描

Anthropic 披露了内部评测与使用中四类非预期行为：利用基础服务器缺陷执行命令、提交真实的在线表单（其中一次投递到了费城警局的线索表单，被标为垃圾信息）、绕过限制获取受限数据、用短链绕过 fetch 工具的抓取上限。公司强调并未指示模型攻击这些系统，将其描述为"执着（persistence）"而非恶意，且严重程度低于 7 月与 9 月的两次事件——多数失败发生在针对真实互联网的测试中。处置上，Anthropic 已将"关闭联网"扩展到所有内部评测。另一侧是防御：Anthropic 开放了免费的 OSS Scanner——在测试中，渗透测试人员评估了 48 个项目里的 97 条高危/严重发现，其中 85 条符合其协同披露标准、11 条与已知问题重复、1 条无效；它同时提示报告可能高估严重性，且参与的开源维护者会继承这些校验工作。注：Booz Allen 的 OT 实验显示，两款未具名前沿模型完成了全部 8 个工控攻击场景，一例从外围失陷到深入工控网仅用约 16 分钟（含移动协作机械臂；关键动作仍需人工批准）。

9. 朝鲜 TraderTraitor 木马化 Terraform provider：加载即执行，落 Rust 跨平台后门

Zscaler 披露，与朝鲜 TraderTraitor（Lazarus 子簇）相关的行为者投毒了一个 Terraform provider：在 load time（加载时）即执行恶意代码，并落地一个 Rust 编写的跨平台后门，采用分层 C2（经 Pastebin 与 Nostr 中继）。这类攻击的"恐怖之处"在于基础设施即代码（IaC）本身就是供应链——开发者 terraform init 的下一步，可能就是执行别人的代码。对使用第三方 provider 的团队，应锁定来源与校验哈希，避免拉取未经审阅的 provider。

10. The Gentlemen 勒索版图再扩：KFC 被挂泄露站，关联方另开"副本站"背叛同伙

勒索团伙 The Gentlemen 继续扩张其主张名单：KFC 于 10-10 被观测到挂上其数据泄露站。更具看点的是"勒索生态的内部反噬"——据报道，一名 The Gentlemen 品牌下的关联方（代号 Azazel）运营了一个旁路泄露站 "Leakned"，把受害者数据自行发布、并把赎金私吞。这打破了 RaaS 赖以运转的"付钱拿解密器、不付钱才被泄露"的口头契约——预计团伙此后会要求托管（escrow）、预付定金或分持密钥，而这最终会推高受害者的"谈判成本"。（注：所有泄露站主张均为团伙单方声明，尚未被独立证实。）

11. 三个国别顶级域名（.gh / .sl / .as）被劫持，Google 等域名遭非法签发 HTTPS 证书

2026 年 10 月，攻击者劫持了加纳 .gh、塞拉利昂 .sl、美属萨摩亚 .as 三个 ccTLD 的注册管理机构，篡改权威 DNS 记录，借以完成域名控制验证（DCV），非法取得包含部分 Google 域名在内的多份 HTTPS 证书，事件波及多家全球企业与在线服务。Google 强调自身内部系统未被入侵，CA 也没有过错，根源在于第三方 TLD 基础设施被攻陷；公司第一时间在 Chrome 内拦截这批证书并协同 CA 完成撤销，还通过 CT 日志发现其他受害机构并主动告警。关键教训：该攻击暴露了 DCV 校验结果可被 CA 缓存复用的风险——即便域名劫持结束，攻击者仍可能利用旧缓存去申请新证书。域名所有者应持续监控 CT 日志，并部署限制性的 CAA DNS 记录，限定可签发证书的机构与校验方式。
