Ghostscript CVE-2026-101258：五段链掀翻 -dSAFER 沙箱，公开 PoC 击穿 ASLR 直取任意命令执行

2026-10-06 公开、10-07 Red Hat 跟进出公告。Ghostscript 的 -dSAFER 沙箱，是它处理不可信 PostScript/EPS/PDF 时唯一的隔离手段，而 CVE-2026-101258（CVSS 3.1 = 7.8，High）把它整个掀掉了。攻击者用 UAF（CWE-416）+ Type 5 Shading 越界写（CWE-787）两枚缺陷组成五段链，在运行时把沙箱开关 path_control_active 置 0，让本应被禁用的 %pipe% 操作符重新可用——在 Ghostscript 进程上下文里执行任意 shell 命令。V12 Security 已在 BSides Canberra 2026 放出公开 PoC，且 Alpine / Arch / Debian / Fedora / Ubuntu 多发行版确认可用。

1 头条事件

Ghostscript CVE-2026-101258（CVSS 7.8）：-dSAFER 沙箱被五段链整体掀翻，公开 PoC 已就绪（头条）

Ghostscript 10.00.0 – 10.07.1 · CWE-416 UAF + CWE-787 越界写 · 修复 GhostPDL 10.09.0 CVE-2026-101258 CVSS 3.1 = 7.8 · 公开 PoC（V12 Security） · Red Hat RHSA-2026:76877

这不是"崩溃级"的内存破坏，而是主动关掉了沙箱的开关。沙箱本应把不可信文档里的一切危险能力挡在外面，-dSAFER 存在的唯一目的就是禁止 %pipe% 之类能调用外部程序的操作。缺陷组合的第一步是 psi/zfproc.c 中过程流字符串的释放后使用（无写屏障，跨 save/restore 后留下悬垂引用），第二步是 base/gsshade.c / gsfunc3.c / psi/zshade.c 中 Type 5 Shading 的越界写（check_CBFD 只校验数组包装器的长度，漏检子函数输出数）。两步合起来，先泄漏指针击穿 ASLR，再内存扫描定位 gs_lib_ctx_core_t.path_control_active，最后把它置 0。

为什么值得关注：

  • 利用门槛已从"研究级"降到"脚本级"：PoC 一公开，任何拿到恶意文档模板的人都能尝试复现，不再需要自己写漏洞利用
  • 部署面极广且藏在后台：Ghostscript 是 ImageMagick、LibreOffice、打印服务、文档转换微服务的后端解析引擎。任何"把用户上传文档喂给 Ghostscript"的流程都是候选目标，而这些流程常常藏在守护进程里，运维视角根本看不见
  • "沙箱孤岛"的代价：把 -dSAFER 当成唯一防线来信任，本身就是失策——这一次它被完整掀翻，说明隔离必须叠加：容器化、降权、只读文件系统、网络出口最小化，缺一不可
  • 修复跟随及时：GhostPDL 10.09.0 源码已含修复（跨空间拷贝 + save-ID 跟踪 + 子函数输出校验）；Red Hat 于 10-07 发布 RHSA-2026:76877 跟进，各发行版随后推进

处置：升级 Ghostscript / GhostPDL 至 10.09.0 及以上（Debian/Ubuntu 用 apt 安全源，Fedora/RHEL 用 dnf / Red Hat 通道）；盘点容器基础镜像与文档处理微服务中的 Ghostscript 版本；把文档处理路径限制为低权用户 + 只读文件系统 + 出站白名单；对打印服务器与对外文档转换入口，按"可能被喂投恶意文档"重新评估暴露面。

为何值得关注：这是隔离机制的失效——我们给不可信内容准备的"笼子"自己出了问题。当"笼子"是本条流水线的唯一防线，而它被公开 PoC 掀翻时，正确的应对不是加厚笼门，而是让笼子外面还有一层。

2 开源 / 满分 CVE

Payload CMS CVE-2026-105857（CVSS 10.0）：一次表单提交即触发未认证远程代码执行

@payloadcms/plugin-form-builder < 3.90.0 · CWE-94 代码注入 + CWE-1321 原型污染 · 修复 3.90.0 CVE-2026-105857 CVSS 3.1 = 10.0 · AV:N/AC:L/PR:N/UI:N/S:C · GHSA-r488-j9vj-wx3q

Payload 是流行的开源 headless CMS，@payloadcms/plugin-form-builder 是它的表单构建插件。CVE-2026-105857 的向量是 AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H——无需认证、无需交互、且影响范围超出组件本身（Scope Changed），攻击者构造一次特制表单提交即可在服务器上执行代码。

  • 为什么是满分：PR:N / UI:N 等价于"互联网上任何脚本都能打"，S:C 又说明被攻陷的进程可以影响宿主机与相邻服务。对公网暴露的表单端点而言，这几乎是最坏的组合
  • 暴露面天然存在：表单是 CMS 面向公网的天然入口，没人会把"联系表单"藏在登录之后。修复版本 3.90.0（canary 4.0.0-canary.34）
  • "改了没生效"的坑：只改 package.json 而运行旧镜像等于没修——必须重建并重新部署产物，并核对 lockfile 与实际容器内版本一致

处置：升级至 3.90.0 / 4.0.0-canary.34+，重建部署；若暂时无法升级，限制表单端点的对外可达性、加认证或严格出口控制；事后轮换进程可触及的数据库、云与签名密钥，并排查 web shell、异常定时任务与出站连接。同生态另有 CVE-2026-106100（PayloadCMS MongoDB 适配器，@payloadcms/db-mongodb < 3.87.0 的字段级写权限绕过，CVSS 7.1）值得一并排查。

为何值得关注：满分 CVE 往往出在"人人都用、却没人细看"的基础组件上。表单构建器看起来只是个"方便的功能"，但它把用户可控输入直接送到了服务器执行路径——这正是代码注入的经典土壤。

3 安全事件 / AI 攻击

韩国 7 家金融机构被"AI 渗透工具"连打：约 6.8 万人资料外泄，疑用开源 ARTEX 编排攻击

2026-10-05 起披露 · 员工与合作伙伴门户为入口 · 撞库 + 参数篡改 约 68,000 人 + 2,200 条企业记录 · 28–33 个攻击 IP · 涉 10 余国家/地区

韩国至少 7 家金融机构遭入侵，调查人员在攻击服务器中发现中文串 "ARTEX-自主渗透测试控制台"。已确认的外泄规模包括：Yegaram 储蓄银行约 40,000 人、Shinhan 银行 25,729 人、Welcome 储蓄银行 2,200 条企业记录、Hyundai Capital 146 名贷款中介、KB Kookmin 119 条、Hana 银行 89 条、BNK 釜山银行 11 名合同工，合计约 6.8 万人 + 2,200 条企业记录。外泄数据含姓名、联系方式、居民登录号、年收入与贷款额度。

  • 打法变了：攻击者没有正面强攻核心银行系统，而是反复试探员工与合作伙伴门户（贷款中介查询、员工销售支持台）——这些系统承载的敏感数据不少，控制却远弱于对外的手机银行。手法涉及撞库 + 参数篡改，也疑似利用了此前泄露的个人信息
  • ARTEX 不是大模型：它是一款由中国网络安全工程师开发的开源自主渗透测试控制台，可调用 Claude Opus、GPT、DeepSeek 等模型编排多个 AI Agent，自动侦察、找洞、规划攻击路径。韩国金融安全院（FSI）明确：是人在操作工具、AI 未自主行动，且无证据表明攻击者来自中国——IP 分布于美、日、德、港、新等 10 余个国家/地区，仅凭 IP 地理无法定位真人
  • 为什么危险：这类工具把过去需要专家逐步手工完成的侦察与试探，压缩成可自动编排的流水线，显著降低了攻击门槛；而被窃的"收入 + 贷款额度"组合，是精准钓鱼与语音诈骗的黄金素材——一个电话能同时报出姓名、住址与贷款额度的"客服"，说服力完全不同

处置：金融机构应复核员工与合作伙伴门户的鉴权强度、限速与撞库防护；对高频、多点、低强度的试探日志重点分析（AI 编排攻击的典型指纹）；对已泄露数据的主体提前发布反钓鱼警示。韩国总统已下令"速度至上"，金融委员会紧急召集 CEO 开会。

为何值得关注：这是"AI Agent 加速攻击"在金融行业的一次落地验证。防线的短板不在核心系统，而在生态里那些"够用就好"的入口——当攻击方用 Agent 把试探成本降到近乎为零，短板效应会被无限放大。

4 数据泄露 / 勒索

日本多起数据泄露与勒索集中爆发：公立大学 500 台服务器停摆，涉数百万用户

2026-10-06 综合报道 · 教育 + 零售 + 金融 · 各起事件相互独立 大阪公立大学 ≥13 万师生 · Mr. Max 170 万 · GMO 94.85 万 · Monogatari 超 1000 万 · 大和证券 11 万

日本多所学校与企业在一周内接连报告数据泄露或网络攻击，各起事件相互独立，却叠加成一次区域性冲击。

  • 大阪公立大学：约 500 台服务器停止运行（疑为勒索），至少 13 万师生姓名、地址、邮箱可能外泄，讲座被迫取消。该校由原大阪府立大学与大阪市立大学于 2022 年合并，遗留系统与新兴架构并存——机构合并往往把两套安全基线拼在一起，形成横向移动的暗道，重建系统时未做统一审计与分段，风险会长期潜伏
  • Mr. Max Holdings（折扣零售）：最多 170 万客户个人数据受影响，网购服务已暂停
  • GMO Research & AI：约 948,500 条会员记录被盗，价值约 290 万日元的积分被非法兑换成亚马逊礼品卡——数据泄露直接变现
  • Monogatari（烤肉连锁 Yakiniku King）：超 1,000 万条客户信息（邮箱、电话）外泄，几乎覆盖全部注册用户
  • 大和证券（Daiwa Securities）：约 11 万客户数据，经承包商服务器中转，暂不能用于交易

处置：受影响主体应及时通知并建议用户警惕钓鱼；企业侧应复盘"承包商 / 遗留系统"这条常被忽视的信任链。对教育机构而言，合并后尤其需要统一身份管理与隔离备份——500 台服务器同时停摆，说明备份与恢复预案很可能没经过"整体沦陷"级别的演练。

为何值得关注：攻击者并不挑行业，挑的是"安全投入与数据价值不匹配"的目标。教育、零售、金融同时中招恰恰说明：只要暴露面足够大、防护相对薄，行业标签并不重要。

5 威胁情报 / 供应链

GlassWorm 借"配色主题"再下手：VS Code 主题内藏下载器与 Solana 隐蔽 C2

Socket《Pretty Themes, Hidden Loaders》· 10-02 公开 / 10-06 持续报道 · Marketplace 4 + Open VSX 6 2 个确认恶意 · 高风险主题 Marketplace 8000+ 安装 · Open VSX 约 39,000 下载

一个与 GlassWorm 高度关联的 VS Code 扩展簇被曝光，其中 2 个确认恶意：

  • Aurora Nocturne Night Theme：冒充 microsoft 发布者身份；公开仓库看着正常，实际分发包是约 59KB、单行混淆的 JavaScript，用零宽 Unicode 字符藏载荷；解码后从 fingercakes4sale[.]store 下载内容，存为 %TEMP%\temp_batch.cmd，再用 cmd.exe 隐藏窗口执行
  • Cosmic Nebula Themes：用 AES-256-CBC 解密内嵌脚本后 eval()；检测到俄语/俄罗斯时区即退出，再读取 Solana 交易备注（dead drop）解析下一阶段下载地址——运营者可不发新版本就轮换投递服务器；其 Solana 地址、密钥与执行模式与既往 GlassWorm 活动一致
  • 高风险待观察：Coca-Cola Christmas 与 Aurora Borealis Studio Theme（Marketplace 合计 8,000+ 安装，含可执行 JS 但未检出载荷）；Open VSX 上 Coca-Cola Christmas 约 39,000 下载、Charcoal Mint 约 10,000。微软已下架被举报扩展，但 Cursor、Windsurf 等 VS Code 分支默认用 Open VSX，只清 Marketplace 不够

处置：清点开发者机器上来自 Marketplace 与 Open VSX 双源的主题扩展；审包而不是审仓库（检查 package.json、激活事件、JS 入口、运行时解密、网络请求与进程执行）；若装过 Aurora Nocturne，排查 fingercakes4sale[.]store 的 DNS/代理命中与 %TEMP% 残留，并轮换本机 SSH 密钥、Git / 云凭据。

为何值得关注：一个配色主题只需要描述"编辑器长什么样"，VS Code 却允许主题携带 JavaScript，且没有细粒度权限控制——这个架构缺口把"主题"变成了"加载器"。又一次证明"审仓库"不等于"审包"：仓库可以干净，分发包却可能是另一副面孔。而这些代码跑在装着 SSH 密钥、Git / 云凭据、CI/CD 密钥的开发者机器上，以用户自身权限运行、无逐条权限提示——这是供应链最薄弱又最高价值的一环。

速览区

6. AhsayCBS CVE-2026-105134 / 105133（CVSS 10.0）：备份平台未认证命令注入

AhsayCBS 备份管理平台存在未认证 OS 命令注入，影响 10.3.0–10.3.2，修复 10.3.4，两枚缺陷均已公开 exploit 代码。备份基础设施是"最后一道防线"——被拿下意味着勒索方连你的底牌一起端走，务必优先处理并校验备份完整性。

7. OrdaSoft Joomla CCK CVE-2026-102427（CVSS 10.0）：uploader.php 未认证 RCE

Joomla 的 OrdaSoft CCK 组件在 < 8.3.16 存在未认证 RCE，入口为 site/uploader.php。网络可达、利用简单，若该组件挂在公网，应优先于其它项修补（升级 8.3.16 或更高）。

8. Progress DataDirect ARCGenAI CVE-2026-91140（CVSS 9.6）：特制 Swagger 文档即命令注入

ARC AI Model Generator 早期版本存在命令注入，特制的 OpenAPI/Swagger 文档即可触发——AI 时代的"文档即载荷"。修复很轻：从仓库拉取最新的 agent 定义即可，无需安装、打补丁或迁移。

9. Totolink A3002MU CVE-2026-105285（CVSS 10.0）：QoS 处理栈溢出，PoC 已释出

/boafrm/formIpQoS 的 QoS 规则处理存在栈溢出，远程无需认证、无需交互即可触发（addQos / comment / entry_name 参数），公开 PoC 已释出。家用/小型路由器广泛部署，属于"补丁未必有、但一定要收敛管理面"的一类。

10. Google Chrome 155.0.8059.39：修复多项缺陷，含 FontAccess 释放后使用

2026-10-07 稳定版更新，修复多项缺陷，其中 CVE-2026-106310（FontAccess 组件释放后使用，可绕过 web 同源策略，需已攻陷渲染进程）与 CVE-2026-102322 等在列。Chrome 更新节奏快，但渲染器沙箱逃逸类缺陷无论评分高低都应尽快跟进。

11. 42 个恶意 RubyGems 包 + SubQuery npm 包被投毒

一批针对加密货币开发者的恶意 RubyGems 包会开反弹 shell 或下载二阶段载荷；同时 SubQuery 生态一个正当 npm 包被植入恶意代码（v5.8.3），在安装或被 import 时即触发，窃取开发机与 CI（含 GitHub Actions）上的凭据与云密钥，并具备远程 shell 能力。用过相关依赖的团队须轮换凭据并排查出站连接。
