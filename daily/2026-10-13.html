CyberXero：51 个 Claude Code 智能体组成攻击流水线，61 秒投下 32 个 WebShell（头条）

SOCRadar 披露 · 俄语系财务动机初始访问中间商 · 至少自 2026-07 起活跃且仍在活动 · 受害者：乌克兰能源与公用事业 + 全球 WordPress/电商 确认窃取超 62.8 万条乌克兰个人记录 · 单次扫描 4,708 目标 / 429 个后台 / 61 秒 32 个 WebShell · 入口 CVE-2026-63030 / 60137 / 4815 · 暴露目录 46.21.250.135

安全厂商 SOCRadar 披露了一个代号 CyberXero 的俄语系、财务动机的初始访问中间商（IAB）：它一边在全球范围内自动扫打 WordPress 与电商站点，一边手工挑选乌克兰能源与关键基础设施目标深挖。至少自 2026 年 7 月起活跃，目前仍在活动，已确认窃取 超过 62.8 万条与乌克兰个人相关的记录，另在波兰、中国、荷兰确认了若干受害站点。

最值得记住的是它的"组织结构"——AI 不是助手，是流水线上的工种：攻击者在自己的主力 Linux 工作站上，把 Anthropic 的 Claude Code 拆成 51 个专用智能体，分别负责扫描、漏洞链编排、侦察与后渗透；在另一台 Cobalt Strike Team Server 上，他又把开源自主渗透智能体 PentAGI 经 AI 供应商 API 接进 Cobalt Strike，用于载荷生成与自动化渗透执行。整条架构由八个节点构成（主力工作站、配置服务器、变现基础设施、载荷暂存服务器、扫描器等）。

自动化跑出来的具体数字（来自泄露的日志）：单次自动执行扫描 4,708 个目标，确认拿到 429 个 WordPress 后台的访问权，并在一个 61 秒的窗口内投下 32 个 WebShell。全球侧的入口主要是 wp2shell（CVE-2026-63030 / CVE-2026-60137） 与 Support Board 插件的 SQL 注入 CVE-2026-4815；此外还打了暴露在公网的 Redis，导致两家中国实体被入侵。定向侧则直指乌克兰能源与公用事业，其中哈尔科夫一家区域供热商因脚本里硬编码的密码，单点泄露 56.4 万+ 条客户记录。

怎么被发现的：又是"自己的服务器裸奔"——攻击者的机器 46.21.250[.]135 是一个没有任何访问控制的开放目录，泄露了 9 万+ 个文件，里面躺着 AI 会话日志、含明文 token 的脚本、漏洞利用工具包、侦察结果、AI 智能体配置和已被窃取的受害者数据。

关于"模型为什么肯干"：SOCRadar 的分析给出了一个对 AI 开发者很关键的观察——模型的安全控制作用于"会话上下文"，而不是模型权重，所以一次拒绝不会带进下一次会话。攻击者用 上下文工程（把任务包装成"对我自己基础设施的授权渗透测试"）加会话重置，反复绕开拒绝。不过日志里也记录了真实生效的拒绝：模型在四次迭代中连续拒绝了装后门、关防火墙、横向移动和投 WebShell，另有一次连续四次拒绝扫描，并正确识破了一个伪造的所有权令牌。

为何值得关注：这起事件是目前 "AI 赋能攻击"最有说服力的一份样本——不是概念演示，而是有日志、有数字、有受害者的实战。它把两件事同时摆到台面上：第一，AI 已经把攻击的"人均产出"抬高了一个量级（61 秒 / 32 个 shell，人类团队做不到）；第二，靠"模型会拒绝"来当防线，是站不住的——拒绝按会话生效，换个说法重开一次就行。防御上，SOCRadar 给出的三个排查锚点很实在：可疑的 WordPress 管理员账号、WSO WebShell，以及 Redis 主机上 ~/.ssh/authorized_keys 里多出来的条目。

2 未认证 root

Dell System Update CVE-2026-86360：路径穿越直通未认证远程 root，PowerEdge 固件通道被打穿

Dell System Update（DSU）CLI 部署工具 · Linux 与 Windows 平台 · 用于批量部署 PowerEdge 的 BIOS / 固件 / 软件更新 86360 路径穿越 → 未认证远程 root RCE · 同批 63697 / 71168 RCE · 86361 / 86362 提权 · 修复 DSU 2.3.0.0+

Dell 就其 System Update（DSU）命令行部署工具发布紧急安全公告：CVE-2026-86360 是一枚路径穿越漏洞，未认证的远程攻击者可利用它在目标主机上以 root 权限执行任意代码。

  • 影响面：DSU 是用来给 PowerEdge 服务器批量部署 BIOS、固件与软件更新的工具，Linux 与 Windows 平台都在用。也正因为这个工具本身就需要高层级权限去改动系统核心组件，一旦漏洞把 root 送出去，等于把服务器的主安全边界整个让了出去——攻击者可以同时操纵硬件层与操作系统层，后果从大规模数据泄露一直到关键基础设施被破坏
  • 修复：Dell 已发布补丁，要求企业客户立即升级到 DSU 2.3.0.0 或更高版本
  • 同批一并修掉的还有四枚高危：CVE-2026-63697 与 CVE-2026-71168（均为 RCE）、CVE-2026-86361 与 CVE-2026-86362（权限提升）
  • 另需连带留意：Dell 另一份公告 DSA-2026-448 修了容器存储模块（CSM）的两枚最高严重级漏洞 CVE-2026-63688 与 CVE-2026-63692（该对漏洞在 10 月上旬已通报，属同一波 Dell 补丁）

为何值得关注：这是典型的"运维工具即最高权限后门"问题。DSU 这类工具在数据中心里的角色是"批量改固件"，为了干这活它必须长着 root 的手；而它同时往往挂在管理网、甚至被自动化平台调用。于是漏洞的利用门槛被压到最低：网络可达 + 无需凭据 = 最高权限。对运维团队的动作很明确：把 DSU 升级到 2.3.0.0+，并顺手盘一遍"还有哪些自带高权限的运维/交付工具暴露在非受控网段"——这类工具的补丁优先级，应该按"它被拿下后能做什么"来排，而不是按"它是不是个漏洞扫描器"来排。

Bricksforge WordPress 插件 CVE-2026-85097（CVSS 10.0）：一个 MIME 校验的落差，未认证直通 RCE

Bricks 建站器的商业扩展插件（不在 WordPress.org 销售，走自建更新通道）· Patchstack 通报 · 受影响 ≤ 3.1.8.9 · 修 3.1.8.10 / 4.0.1 85097 CVSS 10.0（Wordfence 评 9.8）· CWE-434 任意文件上传 · 10-07 21:47 UTC 起在野 · 63 个源 IP · 仍未入 KEV

Patchstack 通报：WordPress 可视化建站工具 Bricks 的商业扩展插件 Bricksforge 存在一枚满分（CVSS 10.0）漏洞 CVE-2026-85097，未认证攻击者可上传并执行任意 PHP 代码，且已在野利用（Wordfence 作为 CNA 给出的 CVSS 3.1 评分为 9.8，Patchstack 评 10.0）。

  • 根因（一个"前后不一致"）：Bricksforge 在文件首次上传时会校验 MIME 类型，但在随后提交表单时，却信任客户端送来的文件元数据——它没有校验 temporaryFileUploads 参数里的 url 字段
  • 四步利用链：① 从未认证的 bricksforge_regenerate_nonce AJAX 接口取到有效 nonce；② 上传一个 GIF/PHP 多形态文件（polyglot）——同时是合法图片又内含 PHP 代码，落在临时上传目录；③ 提交一个表单：服务端文件路径指向那张"已通过校验的图片"，但 url 字段以 .php 结尾；④ Bricksforge 照单全收地把文件内容写到 PHP 路径上——请求它，代码就执行
  • 在野情况：Patchstack 于 2026-10-07 21:47 UTC 首次观测到利用尝试，来自 63 个不同源 IP，其中六个 IP 承担了约 46% 的请求（177.75.57[.]20、23.97.62[.]146、84.247.60[.]125、38.154.185[.]97、150.109.16[.]166、153.75.90[.]146）。流量呈明显自动化特征：一个簇里 44 个 IP 在数秒内发出 56 个完全相同的请求，另一个簇里 3 个 IP 试了 25 种 PHP 扩展名与编码变体（.php5、.php7、.phtml、大小写混用、%70hp、双重编码等）。绝大多数请求打到 POST /wp-json/bricksforge/v1/form_submit，落地文件名形如 login_admin_*.php
  • 修复与状态：升级到 Bricksforge 3.1.8.10 或更高（厂商侧另有 4.0.1 修复版本；3.1.8.9 及更早受影响，4.0.0 也应视为可能暴露）。该插件不在 WordPress.org 官方插件库销售，走自建更新通道，很容易"以为自己会自动更新、其实没更新"。截至 10-13，该 CVE 仍未进入 CISA 的 KEV 目录

为何值得关注：这是一个"校验只做了一半"的经典案例：上传时查了，提交时不查，而攻击者恰好能同时控制这两步。更值得记的是风险判断的教训——一个满分、免凭据、可自动化的漏洞，是否在 KEV 里，和它是否正在被利用，是两回事。自查锚点：翻 Web 日志里带 temporaryFileUploads 参数的表单提交请求，检查 /wp-content/uploads/bricksforge/tmp/ 下有没有你没放过的 PHP 文件（尤其 login_admin_ 开头的），发现即按已失陷处置、轮换凭据。

GitLab 一次修 24 个漏洞：CVE-2026-96893 把"AI 智能体提示注入"写成正式 CVE

GitLab CE / EE · 补丁版本 19.4.2 / 19.3.5 / 19.2.8 · 安全公告 SB2026101301 · 多数漏洞需已认证或特定角色 96893 提示注入 CVSS v4 8.4 · 16301 受保护分支越权执行流水线 7.1 · 81839 迁移项目流水线残留 7.2 · 14552 机密 epic 越权读取 5.3 · 92883 存储型 XSS 5.1

  • CVE-2026-92883（5.1）：语法高亮输出对 HTML 属性净化不当导致存储型 XSS，攻击者可用特制仓库在其他用户浏览器里执行 JavaScript

为何值得关注：这期的信号是——"LLM 提示注入"正在从博客里的攻击演示，变成厂商公告里的正式 CVE。当 AI 智能体被授予读写代码、触发流水线、调用工具的能力时，"输入没有被正确中和"就不再是一个 XSS 级别的小问题，而是一条能借他人身份执行动作的路径。GitLab 把它按 8.4 处理、并和 20 多个其他漏洞一起打包修复，等于在说：智能体平台的安全基线，现在必须和代码仓库本身一个级别。处置侧没有花招：升级到 19.4.2 / 19.3.5 / 19.2.8 及以上；同时给 AI 智能体的工具权限做最小化，别让"能读 issue 的人"顺带拥有"能指挥智能体动 CI/CD"的隐含能力。

SonicWall SMA 1000 CVE-2026-102255 在野确认：135 次利用尝试，凭据与 TOTP 种子被成批薅走

SMA 1000 远程接入设备（机型 6210 / 7210 / 8200v）· 修复 12.4.3-03670 / 12.5.0-03082 · Previdian 与 Defused Cyber 最早捕捉 · Rapid7 观测驻留 102255 预认证 SSRF CVSS 10.0 · 特制 OPTIONS 请求经备用路径打到回环 5984 的 CouchDB · 135 次尝试来自 2 个美国 IP · 仍未入 KEV

10-06 打过补丁、10-08 首次被观测到利用的 SonicWall SMA 1000 预认证 SSRF CVE-2026-102255（CVSS 10.0），在 10-12 有了更硬的在野证据。

  • 漏洞通道：攻击者向 SMA 1000 的 WorkPlace 界面发送一个特制的 OPTIONS 请求，经由一个"非预期的备用访问路径"（unintended alternate access path），打到设备回环地址上的内部 CouchDB 服务（端口 5984）。由于是预认证，不需要任何凭据。受影响机型为 6210 / 7210 / 8200v，受影响固件为 12.4.3-03526 与 12.5.0-02952 及更早
  • 修复版本：12.4.3-03670（平台热修复） 与 12.5.0-03082（平台热修复）
  • 在野数据：Previdian 统计到 135 次利用尝试，来自两个位于美国的 IP（10-09 与 10-10）；Defused Cyber 与 Previdian 是最早在 10-08 捕捉到利用迹象的厂商。Rapid7 称观测到攻击者把暴露的 SMA 设备当作隐蔽初始访问入口，在设备上执行命令并维持长期驻留；站稳之后，他们系统性地提取了高价值凭据、活动会话数据库，以及基于时间的一次性口令（TOTP）多因素认证的种子配置
  • 状态提醒：截至 10-13，该 CVE 仍未进入 KEV，SonicWall 也尚未更新公告去确认在野利用

为何值得关注：这类边缘远程接入设备一直是攻击者最爱的"门"——它天然对外、补丁常常滞后、而且里面塞满了最值钱的东西。这次被盗的不只是密码，还有 TOTP 种子：拿到 MFA 种子，等于把"第二因素"变成了"另一个可以被复制的东西"，这会直接削弱组织对 MFA 的信任。行动项很干脆：升到 12.4.3-03670 / 12.5.0-03082；升级之后务必轮换凭据、作废并重建会话、重新登记 TOTP（补丁清不掉补丁之前就被薅走的种子）；如果暂时升不了，就把 SMA 门户收敛到最小暴露面。

CVE-2026-96119（CVSS 9.9，CWE-94 代码注入）：IBM i 的 HTTP Server Administration 图形管理界面因数据净化不当，远端已认证攻击者可读取敏感信息或执行任意代码（CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:C/C:H/I:H/A:H——注意范围变更 S:C 意味着影响会溢出到其他组件）。影响 IBM i 7.3 / 7.4 / 7.5 / 7.6，修复 PTF：7.6 → SJ11645、7.5 → SJ11644、7.4 → SJ11643、7.3 → SJ11641，无临时缓解措施。另 CVE-2026-90920（CVSS 9.8）：IBM Maximo AI Service 9.1.0 与 9.2.0 因对代码生成的控制不当，远端攻击者可执行任意代码。同批还有 IBM DataStage（Cloud Pak for Data 5.4.0.0）CVE-2026-82103（9.6）。注意：IBM i 这类"跑了几十年的核心系统"，管理界面往往直接挂在企业网里、被当作可信内网组件——9.9 分 + 范围变更说明它不是"关起门来"的问题；而 Maximo AI Service 的"代码生成控制不当"，再次说明AI 服务正以"普通业务组件"的身份进入评分体系，该打的补丁一个也别少。

7. Rapyd Admin CVE-2026-109566（CVSS 9.8）：硬编码的 admin@laravel / admin，每跑一次命令就重建一次

VulnCheck 披露 Rapyd Admin 9.0.0 至 9.20.0 之前存在一枚硬编码凭据（CWE-798）漏洞 CVE-2026-109566：安装器通过 AuthSeeder 种下了一个 admin@laravel 账号，口令就是 admin；更妙的是，这个账号在每次执行 rpd:make 时会被静默重建——管理员就算手动删了、改了密码，下次跑命令它又回来了。攻击者无需认证即可用它登录，成为全局超级管理员，绕过逐记录的授权与多租户隔离（tenant scoping）。修复：升级到 9.20.0 或更高（补丁提交 acd6ee8）。为何值得关注：这是"默认凭据 + 会被自动复活"的叠加伤害——默认凭据本身还能靠"上线后改密码"兜住，但"每次构建都重建"直接把这个兜底废掉了，你的加固会被自己的一次部署覆盖。凡是脚手架/后台生成类框架，都要警惕"开发期便利特性被带进生产"：上线前确认 seeder 与默认账号是否真的关掉了，而不是只看"我第一次登录时改过密码"。

8. Ledger 供应链实锤：授权经销商卖出的硬件钱包里，藏着偷助记词的间谍芯片

Ledger 在 10-11 的 72 小时更新中确认：截至当时所有已确认的"10-09 钱包被清空"事件，涉及的设备都来自东南亚经销商 CryptoBilis；Ledger 强调自身系统与直营渠道未被入侵。第三方链上测算：Bitquery 估算约 9,320 万美元被从 315 个钱包窃取（Tron 约 7,050 万、Bitcoin 约 1,680 万、Ethereum 约 370 万美元），Tether 冻结约 1,000 万美元 USDT（20 个地址）。植入体长什么样：前 Mt. Gox 负责人 Mark Karpelès 称自己在马来西亚买到被动手脚的 Ledger，照片/视频显示屏幕下方（本该是显示缓冲垫的位置）藏了一块小电路板，上面有微控制器、天线、LTE 芯片与一张 eSIM——屏幕显示什么就记什么，在你抄写助记词的那一刻记下来，再发出去；拿到助记词的人可在任何设备上重建钱包、随时清空。为什么"验真"没拦住：Karpelès 说设备开着完好塑封、还通过了 Ledger 的 Genuine Check——因为里面的安全芯片是真的，唯一可靠的发现方式是拆机。处置：CryptoBilis 已停售全部硬件钱包；从该渠道购买且尚未初始化的设备不要初始化，已初始化的应迁到 Ledger 直营渠道的新设备、生成全新助记词；Bitquery 另提示被清空钱包中超八成是在 6 月或更晚才首次收到资金，可能不止"最近 90 天"批次。

9. Cisco Talos：恶意软件开始"反向说服"防守方的 AI——在源码里塞指令，让模型以为"这里不是真目标"

Cisco Talos 发现，一批恶意软件家族内嵌了自然语言指令，用来干扰自动化分析模型：在源码里写入面向 AI 的注释，试图让模型相信"你正在看的不是真实目标"，甚至夹杂恐吓性提示，声称分析环境是一个被监控的蜜罐。受影响的家族包括 FRUITSHELL、PLOTSAFE、HOLLOWCLAD 与 MANTLEMAZE。Talos 指出，这类直接指令式手法已进化到"模板喷洒"——同一份载荷里塞入面向多个模型的指令模板，谁来看都能"照顾到"。为何值得关注：这是攻防在"AI 这一层"上第一次真刀真枪地交手：防守方用模型自动化研判，攻击方就去污染模型的输入。它提醒两件事：第一，"把样本丢给模型让它判断"不能作为唯一定性依据，模型看到的文本本身就是攻击者可写的内容（不可信输入）；第二，检测管线需要"模型之外的锚点"——行为、网络流量、YARA/特征、沙箱动态执行，这些是攻击者没法靠改注释左右的东西。

10. 开源组件集中修复：Apache Struts 四连（S2-075~078）两条分支已 EOL；Elasticsearch 四枚

Apache Struts（10-02 发布 7.4.0 与 6.12.0，10-05 公布 S2-075 至 S2-078）：CVE-2026-104711 是遗留 RESTful action mapper 中的 OGNL 注入，"可能导致远程代码执行"（Apache 自评 Moderate，公告文本未称其为未认证）；另有 CVE-2026-104712（DoS，Moderate）、CVE-2026-104713（REST 插件，DoS，Important）、CVE-2026-104714（数据暴露 + DoS，Moderate）。受影响分支含 Struts 6（< 6.12.0）与 Struts 7（< 7.4.0）；Struts 7 仅在关闭 OGNL 允许列表时受影响。关键提醒：四条受影响范围里，有两条已 EOL、不会再有代码修复——2.0.0–2.3.37（2.3.x 于 2019-09-12 EOL）与 2.5.0–2.5.33（2.5.x 于 2023-10-30 EOL）。缓解手段是改用默认 mapper、restful2 mapper 或 REST 插件。法国 CERT-FR 于 10-09 发布预警（CERTFR-2026-AVI-1290），并未称已观测到利用。另外 Elasticsearch 四枚（CVE-2026-102404 / 102406 / 102413 / 103008）被一并列入本周重点高危清单。为何值得关注：Struts 这条最有价值的不是 OGNL 本身，而是那句"两条分支不再有补丁"——对一个仍在跑 Struts 2.3/2.5 的应用来说，真正的问题不是"这个月补哪个 CVE"，而是"这个应用还打算在互联网上活多久、谁签了字"。

11. P7 DarkSword：iOS 漏洞利用套件升级，直接在设备端抽走钥匙串与加密钱包数据

安全研究者发现 DarkSword iOS 漏洞利用套件的一个新变种，被命名为 P7 DarkSword，能力较前代明显增强：在设备端直接抽取 Keychain（钥匙串）数据，并窃取加密钱包信息——不再是把整个数据库复制出来再远程处理，而是当场取、当场发；建立双向命令控制（C2）通道，可持续下发指令；自带隐藏与痕迹清理行为，使旧的失陷指标（IOC）失效；研究者称该套件通过水坑攻击中的恶意广告分发。为何值得关注：它把"移动端的失陷"从"账号被盗"推进到了"设备里的密钥材料被直接搬走"。对高价值目标（记者、金融与加密资产持有者、企业高管），"iPhone 很安全"这个默认假设需要重新审视——尤其是通过广告投放的规模化水坑，并不需要精确点名某个受害者。
