Cisco Catalyst SD-WAN Manager 曝 CVE-2026-76504：一个编码字符绕过认证，未授权拿下管理员 API

2026-09-30，Cisco 披露 Catalyst SD-WAN Manager 认证绕过漏洞 CVE-2026-76504（CVSS 9.8，CWE-288）。攻击者只需把登录处理路径 j_security_check 里的任一字符做 URI 十六进制编码（如 /%6a_security_check），鉴权规则便匹配不上，请求无凭据直达受保护 API，以 admin 身份获得对该控制台所辖全部 SD-WAN 设备的配置读写权。Cisco 称 9 月已观测到在野利用，CISA 同日列入 KEV，联邦整改截止 10 月 3 日，且官方无任何 workaround。

Cisco Catalyst SD-WAN Manager CVE-2026-76504（×9.8）未认证管理员接管：编码绕过鉴权，KEV 大限 10/3（头条）

Cisco Catalyst SD-WAN Manager（vManage）· CWE-288 · 2026-09-30 披露 · 官方无 workaround CVE-2026-76504 CVSS 9.8 · 未认证 admin API · CISA KEV 9/30 · 10/3 大限

2026-09-30，Cisco 发布安全公告并确认在野利用：Catalyst SD-WAN Manager（原 SD-WAN vManage）存在认证绕过漏洞 CVE-2026-76504（CVSS 9.8，CWE-288）。根因是 API 会话认证管理对 HTTP 请求中的 URI 编码处理不当——攻击者只要在登录处理路径 j_security_check 中对任意一个字符做十六进制编码（Cisco 示例为 /%6a_security_check，%6a 即字母 j），守护该端点的鉴权规则便匹配不上，请求得以在无凭据状态下抵达受保护端点，直接取得 admin（默认持有 netadmin 角色，可执行全部操作）的 API 访问权。

漏洞机制 / 攻击方式：

  • 类型：认证绕过（CWE-288 利用替代路径或通道）／URI 编码处理不当（CWE-177）
  • 攻击方式：向暴露在公网的 Manager API 发送携带 URI 编码字符的特制 HTTP 请求，跳过鉴权规则；%6a 只是示例，任意单个被编码的字符均可触发
  • 影响范围：20.9 < 20.9.10.1、20.12 < 20.12.8.2、20.15 < 20.15.6.1、20.18 < 20.18.4.1、26.1 < 26.1.2.1、26.2 < 26.2.1；早于 20.9 的版本需迁移到受支持修复版本。漏洞与设备配置无关，无功能开关可降低暴露面
  • 后果：vManage 是整张 SD-WAN 的中枢，单实例常管辖数千台设备（部分部署可达 6000 台）；拿下即等于掌握全部受管设备的配置与策略控制权

排查线索（IoC）：审计 /var/log/nms/containers/service-proxy/serviceproxy-access.log，查找来自未知或未授权 IP、路径含编码字符的 j_security_check 请求；审计 /var/log/nms/vmanage-server.log，查找以 viptela-reserved- 开头用户名的相关请求。Cisco 提示此类日志在正常运维中也可能出现，须结合网络基线判断，避免误报。

值得关注的原因：

  • 门槛与影响极端不匹配——「一个 URL 编码字符」换「一张 WAN 的完全控制权」，是典型的打一个点、瘫一张网
  • 这是 2026 年第 5 个在野 SD-WAN 零日；Cisco 今年累计已记录 17 个零日（2025 全年 8 个、2024 年 6 个），边缘网络设备已取代邮件网关成为最热突破口
  • 没有 workaround。只能升级到修复版本；过渡期内须把控制组件收到防火墙之后、仅允许已知可信主机访问管理面，并完成 IoC 排查
2 SOC 平台

AiSOC 五连 CVE：把 CrowdStrike RTR 变成打自己端点的枪（CVE-2026-103056 ×9.0）

AiSOC 5.1.0–11.x · 全部修复于 12.0.0 · 2026-09-30 披露 · 无公开利用 CVE-2026-103056 CVSS 9.0 · 命令注入 · 其余 4 枚均为鉴权缺陷

2026-09-30，开源安全运营平台 AiSOC 一次性披露 5 个漏洞，全部修复于 AiSOC 12.0.0。最严重的是 CVE-2026-103056（CVSS 9.0，CWE-78）：actions 服务在 crowdstrike_rtr.py / endpoint.py 中拼装 CrowdStrike Real Time Response 命令串时直接插值未转义的用户参数，认证用户注入一个单引号即可逃逸引号边界，从而在受管端点以 SYSTEM / root 权限执行任意命令——把防御方的处置通道反向武器化。

另外 4 枚全部打在平台自身的认证层：CVE-2026-103055（7.5，CWE-321）实时 WebSocket/SSE 服务使用硬编码 JWT 密钥，可跨租户读取实时数据；CVE-2026-103054（7.1，CWE-639）允许已认证的 MSSP 用户认领任意租户并读取其告警、事件与态势数据；CVE-2026-103053（CWE-306）在 dev 模式启用且服务令牌为空时，actions 服务缺失认证，可直接派发响应动作；CVE-2026-103057（4.3，CWE-306）允许未认证向内部实时端点投递事件。

值得关注：这是「防御工具自身成为攻击面」的又一实例，且 CVE-2026-103053 在默认 Docker Compose 部署下即可利用（AISOC_DEV_MODE 默认开启、服务令牌从未生成）。修复动作：升级至 12.0.0，显式设置 AISOC_ACTIONS_SERVICE_TOKEN 与 AISOC_REALTIME_JWT_SECRET，关闭 dev 模式，并审计 CrowdStrike RTR 调用日志中是否存在命令注入迹象。

3 供应链投毒

PhantomSub：101 个恶意 npm 包劫持 WhatsApp 会话，累计 49 万次下载

OX Security 披露 · Baileys 库 fork 投毒 · 截至 9/28 npm 仅下架 16 个 约 490,000 次下载（近 30 天 116,000）· 无声订阅频道

OX Security 披露代号 PhantomSub 的供应链投毒活动：101 个伪装成开源 WhatsApp Web API 库 Baileys 衍生版本的 npm 包，在开发者建立已认证会话后，用其账号静默关注/加入攻击者控制的频道与群组。研究者 Nir Zadok、Moshe Siman Tov Bustan 与 Vitalii Chepurko 拆出三种变体：19 个包在运行时从 GitHub 拉取频道 ID（可随时换目标、无需发新版），60 个把频道 ID 明文写死在源码里，14 个以编码/混淆形式内嵌。

这批包累计下载约 490,000 次，近 30 天仍有 116,000 次；截至 9/28，npm 只下架了其中 16 个。目标频道多为印尼小型「卖号 / 卖脚本 / 游戏资源 / 刷粉」社群，粉丝数即社会证明；多个包共享同一批频道 ID 与 GitHub 账号，指向同一个受益人。前情是 2026 年 8 月 SafeDep 已报告过从事类似行为的 Baileys 恶意 fork，Xygeni 亦披露过 @dappaoffc/baileys-mod——同一套路在持续演进。

值得关注：这类攻击不偷密钥、不投勒索，只「偷流量」，调用的是合法 API，行为与预期功能难以区分，因此静态签名扫描与依赖漏洞扫描几乎无感——这是传统工具链的结构性盲区。建议：立即审查依赖树（对照已公布包名清单）、检查关联 WhatsApp 账号是否被塞入陌生群组并退出、避免使用任何需要接入个人 WhatsApp 会话的包，并对 fork 类依赖建立人工 diff 审查流程。

4 浏览器

Chrome 154.0.8037.57 修复 V8 类型混淆与 XML 实现缺陷（各 8.8）

Google Chrome Stable 154.0.8037.57 · 2026-09-30 披露 · 未见公开利用 CVE-2026-95306 V8 类型混淆 8.8 · CVE-2026-95369 XML 实现不当 8.8

2026-09-30 披露两枚高危漏洞，均需用户访问特制页面触发，可在浏览器沙箱内执行任意代码：CVE-2026-95306（CWE-843，V8 引擎类型混淆）与 CVE-2026-95369（CWE-841，XML 处理组件实现不当）。两者 CVSS 均为 8.8（AV:N/AC:L/PR:N/UI:R/S:U/C:H/I:H/A:H），无凭据要求，仅需诱导用户访问恶意 HTML 页面。Chromium 内部将二者评为 Medium，但按 CVSS 计分仍属高危。修复版本为 154.0.8037.57 及以后，同版本还包含多项其它安全修复。

值得关注：浏览器仍是「一次点击即 RCE」的主要入口，而 V8 类型混淆历来是沙箱逃逸链的常见一环，一旦与沙箱逃逸缺陷组合即可能演变为完整的本地代码执行链。企业应通过 GPO/MDM 强制更新并开启自动更新，EDR 侧关注 Chrome 进程派生出的异常子进程与可疑外联。

5 AI 勒索

TheGentlemen 用 AI 代理跑勒索：单次攻击成本低至 0.4–4 美元，一台服务器堆 3.1TB 赃物

Cybernews 调查 · 30+ 受害企业 · 86 个 AI 生成脚本 · 联盟制 RaaS 单次攻击 token 成本 $0.40–$4.00 · 行业全覆盖

Cybernews 发现一台属于 TheGentlemen 联盟成员的服务器：上面存有来自 30 多家公司的 3.1 TB 被盗数据、一个 AI 代理以及 86 个 AI 生成脚本。研究者称，该代理自主完成了整条攻击链——搜索受害企业网络、提取敏感数据、为每套环境定制脚本、起草勒索信；操作者基本只需提供「一个目标和一组登录凭据」。按研究者估算，单家企业攻击的 token 成本低至 0.40–4.00 美元（不含支撑基础设施成本）。

团伙背景：TheGentlemen 2025 年年中崛起，以「90% 分成」招募联盟成员，泄露站已列 200+ 受害组织、覆盖 50+ 国家与 20+ 行业。Black Kite 9 月 17 日报告将其列为今年制造业第二大勒索团伙（1–7 月 142 家受害）；Halcyon Q2 报告称其 6 月已超越 Qilin，并配备可关闭数十种安全产品的定制工具链。

值得关注：

  • 攻击的边际成本被压到「几美元」，目标画像从大型企业下沉到年营收 1000 万至 1 亿美元的中型企业——这类公司停产即亏钱，且通常没有 7×24 监控
  • 修复窗口同步坍缩：Food and Ag-ISAC 9 月报告指出，过去需要数天才能写出的利用代码，现在几小时内即可生成
  • 防御重心需从「防住」转向「假设会被打进来」，把快速检测、自动遏制与可靠恢复作为核心能力

速览区

6. Advantech 遭 Chaos 勒索，工业物联网供应链敲响警钟

Chaos 勒索团伙 9/30 将台湾工业物联网与嵌入式计算大厂 Advantech 列入泄露站。作为全球供应链关键厂商，若固件、源码或更新机制被触及，单点入侵可能放大为供应链攻击；截至报道时公司尚未公开发声。

7. FBI 招聘门户被 ShinyHunters 入侵，FBI 公开喊话

FBI 9/30 公开确认正追查 ShinyHunters 对该局求职门户的入侵，被访问数据库含求职与晋升申请、以及医疗与家庭数据。FBI 认为攻击者可能利用了第三方软件漏洞，多数受影响员工尚不清楚自己的数据是否被取走。

8. 日本 9 月数据泄露潮：16 起通报，Gyazo 2362 万条领跑

9 月日本几乎每天有通报：Gyazo 约 2362 万条用户记录与约 49 亿条图片元数据、村内.com 771 万条、Times Car 约 660 万账户（其中约 160 万含证件影像）、数字厅 GSS 约 24.6 万条。人像证件类数据外泄的二次滥用风险尤其值得警惕。

9. 麦当劳印尼客户数据平台 4000 万记录暴露

暴露数据库共约 4000 万条记录，含 2800 万条客户记录（姓名、邮箱、电话、设备 ID）与 7.1 万条广告投放记录；研究方通报后数据库已关闭。风险点是社交工程邮件/电话增加，以及绑定积分交易信息带来的积分盗刷。

10. 医疗设备厂商 Medela 42.4 万账户泄露

瑞士医疗设备公司 Medela 遭 ShinyHunters「付钱或公开」勒索，数据被公开后 9/30 经 Have I Been Pwned 确认为真实泄露，涉 423,947 个邮箱（多为医疗从业者），暴露字段含公司、职位、姓名、电话与地址。

11. 新加坡首例「AI 相关」数据泄露：美珍香 9.5 万客户邮箱互相可见

美珍香员工用 AI 工具生成群发邮件的 Python 脚本，未要求隐藏收件人地址，导致 95,364 名客户邮箱彼此可见。PDPC 9/30 定性为人为提示失误而非 AI 工具故障——首例被官方归入「AI 相关」的泄露，为「用 AI 写生产脚本却跳过评审与测试」敲响警钟。
